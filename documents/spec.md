## 1. 개요

### 1.1 목적

**8~10명**(짝수)이 참가하는 리그 오브 레전드 내전에서, 플레이어 간 실력 차이를 분석하고 **균형 잡힌 팀 구성**을 제안한다. (8명 → 4:4, 10명 → 5:5)

핵심 가치는 **시험 판 결과를 반영한 다음 판 팀 밸런스 제안**이다. **최대 3판**까지 결과를 입력하고, **2·3·4판**까지 팀을 제안한다. 1판 전에는 공개 데이터 기반 사전 분석을, 각 판 후에는 경기 결과를 **70:30 누적** 반영한다.

### 1.2 대상 사용자

- 친목·동아리·회사 등에서 정기적으로 내전을 진행하는 LoL 플레이어 그룹
- 팀 나누기를 담당하는 **내전 총무**(운영자) 1명
- 별도 계정 가입 없이, Riot ID만으로 참가자를 등록

### 1.3 용어 정의

| 용어 | 정의 |
|------|------|
| **세션** | 한 번의 내전(최대 10명)을 관리하는 단위. localStorage에 저장 |
| **참가자** | 세션에 등록된 플레이어 1명 |
| **전력** | 랭크 티어·최근 경기·숙련도·시험 판 성과를 종합한 실력. **LoL 티어+구간**으로 표현 |
| **개인 점수** | 팀 분배용 내부 점수 (LP 70% · KDA 20% · 승률 10%). UI 노출 안 함 |
| **판 (Round)** | 1~4. 1판=사전 제안, 2~4판=재밸런스 제안. **시험 판 입력은 1~3판만** |
| **내부 티어 (1~4 / OP)** | 세션 상대 등급 (1판 전). **뱃지 표시용**, 팀 전력·배정 계산에 영향 없음 |
| **꿀벌 마크** | 해당 판에서 사전·티어 기대치를 **모두** 초과 시 달성. **연속 스트릭**에 따라 등급 승급 (D-07) |
| **꿀벌 스트릭** | 연속 꿀벌 판정 횟수. 한 판 미달 시 0으로 리셋 |
| **시너지** | 팀 구성의 질. MVP에서는 **표시·근거만** |
| **시험 판** | 각 판(1~3) 종료 후 입력하는 경기 결과 |
| **재밸런스** | 시험 판 결과 후 **다음 판**(2·3·4판) 팀 구성을 제안하는 기능 |

## 2. 사용자 시나리오

### 시나리오 A — 사전 분석 후 1판 진행

1. 총무가 세션을 생성한다.
2. 8명 또는 10명의 Riot ID를 등록한다.
3. 앱이 각 참가자의 전력(티어 기준)·내부 티어 뱃지·시너지 요소를 분석·표시한다.
4. 앱이 1판용 팀 구성(블루/레드)을 제안한다.
5. 총무가 제안을 참고·수동 조정한 뒤 1판을 진행한다.

### 시나리오 B — 시험 판 결과 반영·다음 판 재밸런스 (핵심)

1. 1판 종료 → **1판 결과 입력** → LP 누적·꿀벌 판정 → **2판 팀 제안**
2. 2판 진행 후 → **2판 결과 입력** → LP 누적·꿀벌 판정 → **3판 팀 제안**
3. 3판 진행 후 → **3판 결과 입력** → LP 누적·꿀벌 판정 → **4판 팀 제안**
4. (선택) 4판 전 팀 화면에서 **수동** 새 팀 구성

각 단계에서 변경 근거(이동 인원, 티어 변화, 꿀벌 등급, 시너지)를 확인한다.

### 시나리오 C — 시험 판 없이 또는 중간까지

1. 세션 생성 및 참가자 등록
2. 전력·시너지 분석 및 1판 팀 제안만 확인
3. 또는 1~2판까지만 결과 입력 후 종료 가능

## 3. 설계 결정

### D-01. 세션 저장 — **확정: localStorage**

| 항목 | 결정 |
|------|------|
| 저장소 | 브라우저 `localStorage` only |
| 세션 식별 | UUID 기반 `sessionId` |
| 재접속 | 동일 브라우저에서 세션 목록·세션 ID로 재진입 |
| 제한 | 기기·브라우저 변경 시 세션 소실 — MVP에서 허용 |

**수용 기준**

- [ ] 새로고침·탭 재오픈 후에도 세션 데이터가 유지된다.
- [ ] localStorage 용량 초과 시 사용자에게 안내한다.

---

### D-02. 사전 데이터 vs 시험 판 가중치 — **확정: 70:30 (매 판 누적)**

| 단계 | 사전·직전 LP | 시험 판 | 이유 |
|------|-------------|---------|------|
| **1판 팀 제안** | 100% (사전 LP) | 0% | 시험 판 전에는 랭크·최근 지표만 |
| **각 시험 판 후** (1·2·3판) | 70% | 30% | 직전 LP를 주축으로, 해당 판 성과만 보조 반영 |

**내부 계산 방식**

1. 각 참가자의 랭크를 내부 **LP 환산값**으로 변환한다. (예: 골드 2 50LP → 1,850)
2. 주 선호 라인 평균 KDA·보정 승률을 개인 점수 필드에 포함한다. (D-06)
3. **매 시험 판**(1·2·3판) 종료 후, 해당 판 개인 성과를 **기대치 대비 지표**로 환산한다.
   - 기대치: 해당 판 **소속 팀** 내 LP 비율 — LP 조정과 **꿀벌 티어 기대치**(D-07)에 공통 사용
   - **주 지표: KDA + 딜량** (경기 ID 조회 시 Match API)
4. 기대치 대비 초과/미달에 따라 LP 환산값을 **±1~2구간** 범위 내에서 조정한다.
5. **매 판 누적 LP** = `직전 LP × 0.7 + 해당 판 시험 조정 LP × 0.3`
   - 1판 전 `직전 LP` = 사전 LP (`preLpValue`)
   - 2·3판 전 `직전 LP` = 이전 판 누적 후 `currentLpValue`
6. 최종 LP를 **가장 가까운 티어+구간**으로 표시한다 (`currentTier`).

**수동 입력(승패만)일 때**

- KDA·딜량 없으면: 승리 팀 +0.5구간, 패배 팀 −0.5구간 (팀 단위)
- 상세 데이터 있을수록 개인 단위 조정 비중 확대

**수용 기준**

- [ ] 1판 제안 전력은 Riot API 랭크 데이터만 반영한다.
- [ ] 각 시험 판 후 "반영 전 티어 → 반영 후 티어" 변화가 참가자별로 표시된다.
- [ ] 3판까지 LP가 순차 누적된다.
- [ ] 가중치(70:30)·시험 판 지표(KDA+딜량)가 근거 패널(F-07)에 표시된다.

### D-03. 전력 표현 · LP 규칙 — **확정**

| 항목 | 결정 |
|------|------|
| 표시 형식 | `아이언 4` ~ `챌린저` |
| LP | 같은 구간 내 LP 보조 표시 (예: `플래티넘 2 · 67LP`) |
| 팀 전력 | 팀원 LP 환산값 **평균** → 티어로 환산 (예: `팀 평균: 골드 1`) |
| 팀 간 비교 | LP 환산 차이를 구간 단위로 표시 (예: `약 1.2구간 차이`) |

#### 솔로 / 자유 랭크 — **확정: 솔로 우선**

1. **솔로 랭크**가 있으면 솔로 티어·LP를 사용한다.
2. 솔로가 없고 자유 랭크만 있으면 자유 랭크를 사용한다.
3. 둘 다 있으면 **솔로만** 사용한다. (자유는 표시용 보조 정보로만 가능)

#### 언랭크 — **확정: 최근 시즌 티어 → 없으면 수동 입력**

1. 현재 시즌 솔로·자유가 모두 없으면, **과거 시즌 랭크 이력**을 조회한다.
2. **가장 최근 시즌의 티어**를 입력한다. (근거 패널에 "시즌 XX 기준" 표시)
3. 전 시즌 이력이 **아예 없으면** 총무에게 **수동 티어 입력**을 요청한다.
4. 수동 입력 전까지 해당 참가자는 팀 제안에서 **미완료** 상태로 표시한다.

**수용 기준**

- [ ] 0~100 점수 등 임의 스케일을 사용자 UI에 노출하지 않는다.
- [ ] Data Dragon 티어 엠블럼과 함께 표시한다.
- [ ] 솔로 우선 · 언랭크 최근 시즌 · 수동 입력 흐름이 동작한다.

### D-04. 시너지 점수 — **확정: 표시·근거만 (MVP)**

시너지는 개인 전력과 별도로 **팀 구성의 질**을 나타내는 지표다.  
MVP에서는 팀 제안 **후 표시·근거**만 제공하며, 알고리즘 배정에는 사용하지 않는다.

**MVP 시너지 요소**

| 요소 | 데이터 출처 | 설명 |
|------|------------|------|
| **듀오 이력** | Match V5 (세션 참가자 간 공동 경기) | 공동 승률·KDA. 같은 팀이면 시너지 ↑ |
| **포지션 보완** | Match V5 (최근 N판 주 포지션) | 팀 내 라인 겹침이 적을수록 시너지 ↑ |
| **챔피언 풀 보완** | Champion Mastery V4 | 모스트 챔피언 중복이 적을수록 시너지 ↑ |

**표시**

- 팀별 **시너지 등급**: `높음` / `보통` / `낮음`
- 근거 패널: "A·B 듀오 승률 68%", "정글·미드 포지션 겹침" 등

**수용 기준**

- [ ] 1~4판 팀 제안 UI에 팀별 시너지 등급이 표시된다.
- [ ] 시너지 근거를 펼쳐 볼 수 있다.

### D-06. 팀 분배 알고리즘 — **확정**

#### 개인 점수 (Personal Score) — **확정: LP 70% · KDA 20% · 승률 10%**

| 구성 요소 | 가중치 | 데이터 출처 | 정규화 |
|-----------|--------|------------|--------|
| **LP 환산값** | 70% | League API (**솔로 우선**, D-03) | OP 제외 n명 min-max → 0~1 |
| **주라인 KDA** | 20% | Match API (최근 20판, 주 포지션) | OP 제외 n명 min-max → 0~1 |
| **보정 승률** | 10% | F-03 승률 보정 공식 | 이미 0~1 |

```
personalScore =
  normLp(lpValue)       × 0.70
+ normKda(mainRoleKda)  × 0.20
+ adjustedWinRate       × 0.10
```

- `personalScore`는 **팀 배정·라이벌 매칭**에 사용한다.
- UI에는 **LoL 티어**(D-03)만 주 표시. `personalScore`는 노출하지 않는다.
- 2판 이후 재밸런스 시 **누적** `currentLpValue`를 `normLp` 입력으로 사용한다.

#### OP · 내부 1~4티어 — **확정**

**역할 분리**

| 지표 | 용도 | 팀 전력·배정 영향 |
|------|------|-------------------|
| **personalScore** | 라이벌 페어링·팀 배정 계산 | ✅ 사용 |
| **LoL 티어** | 사용자 주 표시·팀 평균 티어 | ✅ 표시 |
| **OP / 1~4 뱃지** | 사람이 한눈에 보는 **상대 등급** (1판 전) | ❌ 영향 없음 |
| **꿀벌 마크** | **매 판** 기대 이상 성과 (1~3판, D-07) | ❌ 영향 없음 |

**OP 판정**

```
sessionMean = Σ personalScore / n   (전원 기준)
OP ⇔ personalScore ≥ sessionMean × 1.25
```

- OP가 **2명 이상**이면 **전원 OP 뱃지**. 복수 OP 허용.
- OP는 **1~4티어 산출에서 제외**. 나머지 비OP로 1~4 티어(4분위)를 **재확립**한다.
- OP도 **라이벌 페어링·팀 배정에는 포함** (8·10명 알고리즘 동일).
- 내부 1~4 / OP는 **뱃지 표시 전용**. 팀 평균 티어·합계·배정 점수에는 쓰지 않는다.

**산출 순서**

1. 전원으로 `personalScore` 산출 (1차, 정규화는 전원 또는 임시)
2. OP 판정 (`≥ 평균 × 1.25`)
3. OP 제외 후 min-max 재정규화 → 최종 `personalScore` (배정용)
4. 비OP만으로 1~4 티어(4분위) 재확립 → 뱃지
5. OP 뱃지 부여 → Step 1 페어링 (전원 포함)

#### 인원 — **확정: 짝수 8·10명, 동일 알고리즘**

| 인원 | 라이벌 페어 | 팀 구성 |
|------|------------|---------|
| 8명 | 4쌍 | 4 vs 4 |
| 10명 | 5쌍 | 5 vs 5 |

- 팀 나누기(F-04)는 **짝수 n ∈ {8, 10}**일 때 동작. 홀수·6명 이하 → 비활성 + 안내.
- 한 팀 목표 전력 = `세션 personalScore 평균 × (n / 2)`.

#### 핵심 알고리즘 (4단계)

**Step 1. 라이벌 페어링**

- `personalScore` 오름차순 정렬 후 **인접 2명씩 페어링** (1–2, 3–4, …).
- 각 플레이어는 정확히 1명의 라이벌.

**Step 2. 팀 배정 — 완전 탐색 (2^k)**

각 페어 `(high, low)`에 대해:

- **선택 A:** high → 블루, low → 레드
- **선택 B:** high → 레드, low → 블루

k쌍 → 2^k 가지 (8명→16, 10명→32). 최적 선택 기준:

1. `|블루 합 − 레드 합|` 최소
2. 동점 → `ideal = sessionMean × n/2`에 더 가까운 쪽
3. 동점 → 라이벌이 서로 다른 팀에 있는 쌍 수 최대

**Step 3. 오프라인 전력 보정 (분석)**

- 주 선호 라인과 다른 포지션일 경우, 해당 라인 전적(KDA·승률)으로 **표시용** 전력 보정.
- Step 2 배정 결과는 **변경하지 않음**.

**Step 4. 근거 출력**

- 라이벌 페어, OP/1~4 뱃지, **꿀벌 등급**, 팀별 합계·ideal 차이, 재밸런스 시 이동 인원·사유.

**제약**

- 블루/레드 각 `n/2`명
- 전력(personalScore) 합계 차이 최소 — Step 2로 보장
- 시너지: 제안 **후** 표시만 (D-04)
- 재밸런스 시 직전 판 대비 변경 인원·이유 산출 (2·3·4판)

---

### D-07. 꿀벌 마크 — **확정: 시험 판 초과 성과 + 연속 누적 등급**

**1~3판** 각각 시험 판 분석 후, 해당 판에서 **사전 개인 스탯 기대치**와 **티어 기대치**를 **모두** 초과한 참가자에게 그 판 **꿀벌 판정**을 기록한다. OP/1~4와 동일하게 **표시 전용**이며, 팀 배정·LP 조정·personalScore에는 영향 없다.

#### 역할

| 뱃지 | 시점 | 기준 | 배정·전력 영향 |
|------|------|------|----------------|
| OP / 1~4 | 1판 전 (F-03) | 세션 personalScore | 없음 |
| **꿀벌 계열** | 1~3판 각각 (F-05) | 해당 판 사전 스탯 + 티어 기대 초과 | 없음 |

#### 연속 스트릭 · 뱃지 등급

| 연속 꿀벌 판정 | 뱃지 (`honeyBeeBadge`) |
|----------------|------------------------|
| 0회 (미달 또는 리셋) | `none` |
| 1회 연속 | `bee` (꿀벌) |
| 2회 연속 | `glitterBee` (반짝이는 꿀벌) |
| 3회 연속 | `rainbowBee` (무지개 꿀벌) |

- **매 판** D-07 판정 수행. 한 판이라도 미달 → 스트릭 **0 리셋**
- OP + 꿀벌 계열 동시 표시 가능

#### 성과 합산 점수 (내부, UI 미노출)

```
trialScore = normTrialKda × 0.5 + normTrialDamage × 0.5
```

- `normTrialKda`, `normTrialDamage`: **해당 판** 경기 n명 내 min-max (0~1). min = max이면 0.5.

#### 기대치 A — 사전 개인 스탯 (1판만)

- **1판:** F-03 주 포지션 최근 20판 평균 KDA·딜량
- `preStatScore = normPreKda × 0.5 + normPreDamage × 0.5`
- `normPre*`: 세션 참가자 전원 사전 스탯 min-max

#### 기대치 A' — 2·3판 (티어 기반 사전 스탯)

- **2·3판:** 기대치 A는 **직전 누적 LP 기반 티어 기대치**와 동일 로직으로 산출한 **개인 기대 KDA·딜량**을 사용 (해당 판 직전 `currentLpValue` 비율)

#### 기대치 B — 티어 기대치 (D-02, 매 판)

- 출처: **해당 판** 소속 팀 내 LP 환산값 비율
- `tierExpectRatio = playerLp / teamLpSum`
- 팀 전체 해당 판 KDA·딜량 합 × 비율 → `tierExpectScore`

#### 꿀벌 판정 (해당 판)

```
roundHoneyBee =
  trialScore > preStatScore   // 1판: F-03 사전 / 2·3판: A'
  AND trialScore > tierExpectScore
```

- **strict greater** (`>`)
- KDA·딜량 없음 → 해당 판 꿀벌 **미판정**, 스트릭 리셋

#### 기대 이하 판정 (해당 판, F-08 `friend` 모드용)

꿀벌(기대 이상)과 **동일한 `trialScore`·기대치 A/A'·B**를 사용한다. 판정만 반대다.

```
roundBelowExpect =
  trialScore <= preStatScore
  AND trialScore <= tierExpectScore
```

- 꿀벌과 **대칭**: 둘 다 초과 → 기대 이상, **둘 다 이하(또는 동일)** → 기대 이하
- KDA·딜량 없음 → 기대 이하 **미판정**
- **표시 전용**. 팀 배정·LP·personalScore에 영향 없음
- **일반 모드(`normal`)**에서는 UI·AI 요약에 노출하지 않음
- **찐친모드(`friend`)**에서만 `범인 후보` 마크·직설 코멘트 입력에 사용

#### UI

- LoL 티어·OP/1~4 옆에 꿀벌 등급 뱃지 (MVP: 텍스트/간단 SVG)
- F-05 완료 후, F-06, F-07 근거 패널
- 근거 예: "2판 연속 기대 이상 → 반짝이는 꿀벌"

**수용 기준**

- [ ] 1~3판 각각 KDA+딜량 있을 때 꿀벌 판정·스트릭 갱신
- [ ] 사전 스탯·티어 기대 **둘 다** 초과 시에만 해당 판 달성
- [ ] 기대 이하는 **둘 다** `<=` 기대치일 때만 판정 (`friend` 모드 전용 노출)
- [ ] 3판 연속 달성 시 무지개 꿀벌 표시
- [ ] 미달 판 이후 스트릭 리셋
- [ ] 승패만 입력 시 꿀벌 미판정
- [ ] 꿀벌이 팀 배정·LP 갱신 결과를 변경하지 않음

### D-08. Data Dragon 정적 에셋 — **확정**

플레이어 프로필 아이콘, 챔피언 이미지, 티어 엠블럼은 Riot Games가 공식 제공하는 **Data Dragon CDN**을 사용한다. 비공식 웹사이트 이미지를 크롤링하거나 파일을 직접 복제하지 않는다.

#### 기본 원칙

- Riot API와 Data Dragon을 함께 사용한다.
- Data Dragon 이미지 요청에는 **Riot API Key를 사용하지 않는다**.
- Riot API Key는 서버에서만 사용하며, 클라이언트 코드·Git 저장소에 포함하지 않는다.
- Data Dragon 버전은 화면과 API 코드에 중복 하드코딩하지 않는다.
- 이미지 로딩 실패 시 대체 이미지를 표시한다.
- 이미지와 챔피언 데이터는 앱 전역에서 **동일한 Data Dragon 버전**을 공유한다.

#### 버전 조회 · 캐시 · fallback

- 버전 목록은 `GET https://ddragon.leagueoflegends.com/api/versions.json` 에서 조회한다.
- 응답 배열의 첫 번째 항목을 최신 버전으로 사용한다.
- **매 요청마다 조회하지 않고**, 서버 또는 애플리케이션에서 캐시한다.
- 버전 조회 실패 시 설정된 fallback 버전을 사용한다.

예상 응답:

```json
[
  "16.14.1",
  "16.13.1"
]
```

#### 프로필 아이콘

- Summoner API 응답의 `profileIconId`를 사용한다.
- URL 형식:

```
https://ddragon.leagueoflegends.com/cdn/{version}/img/profileicon/{profileIconId}.png
```

- `profileIconId`가 존재하면 프로필 아이콘을 표시한다.
- `profileIconId`가 없거나 이미지 로딩 실패 시 기본 프로필 이미지를 표시한다.
- 이는 Riot 계정의 업로드 이미지가 아니라 **소환사 프로필 아이콘**이다.

#### 챔피언 데이터 · 매핑

- 한국어 챔피언 목록은 다음 주소에서 조회한다.

```
https://ddragon.leagueoflegends.com/cdn/{version}/data/ko_KR/champion.json
```

- 챔피언 데이터는 요청할 때마다 다시 조회하지 않고 캐시한다.
- Match API의 숫자형 `championId`는 Data Dragon의 문자열 `key`와 매핑한다.
- 절차:
  1. `champion.json`에서 `key === championId` 항목을 찾는다.
  2. 해당 항목의 `id`를 가져온다. 예: `103 -> Ahri`
  3. URL 생성에는 한국어 `name`이나 숫자 `championId`가 아니라 **Data Dragon `id`**를 사용한다.
- 오공처럼 표시 이름과 내부 `id`가 다른 경우를 고려해, **반드시 매핑을 거친다**.

#### 챔피언 이미지 URL

목록, 작은 카드, 전적과 통계 영역에는 정사각형 아이콘을 사용한다.

```
https://ddragon.leagueoflegends.com/cdn/{version}/img/champion/{championDataId}.png
```

큰 카드, 상세 화면, 배경에는 Splash Art를 사용한다.

```
https://ddragon.leagueoflegends.com/cdn/img/champion/splash/{championDataId}_0.jpg
```

세로 비율 이미지가 필요하면 Loading 이미지를 사용한다.

```
https://ddragon.leagueoflegends.com/cdn/img/champion/loading/{championDataId}_0.jpg
```

#### 제외 범위

- 스킨 이미지는 현재 MVP 범위에서 제외한다.
- 추후 스킨 기능을 구현할 때만 개별 챔피언 JSON의 `skins[].num`을 사용한다.
- 이미지 존재 여부를 확인하지 않고 스킨 URL을 임의 생성하지 않는다.

#### 권장 타입

```ts
type ChampionSummary = {
  id: string;
  key: string;
  name: string;
  title: string;
  image: {
    full: string;
  };
};

type DataDragonImageUrls = {
  square: string;
  splash: string;
  loading: string;
};
```

**수용 기준**

- [ ] Data Dragon 공식 CDN만 사용하고 비공식 이미지 크롤링을 하지 않는다.
- [ ] `versions.json` 실패 시 fallback 버전으로 일관된 URL을 생성한다.
- [ ] 앱 전역에서 이미지와 챔피언 데이터가 동일한 Data Dragon 버전을 사용한다.
- [ ] `championId`는 매핑 후 Data Dragon `id`로 이미지 URL을 생성한다.
- [ ] 프로필 아이콘·챔피언 이미지 로딩 실패 시 대체 이미지가 표시된다.

### F-03. 참가자 전력 분석 (사전)

**목적:** 시험 판 이전, 공개 데이터로 각 참가자 전력을 **LoL 티어**로 표시한다.

**요구사항**

- League API: **솔로 우선** 티어·LP·승률 (D-03). 언랭크 시 최근 시즌 → 수동 입력
- Match API: 최근 20판 요약 (KDA, CS, 피해량, 시야, 주 포지션) — **꿀벌 마크 사전 기대치(D-07) 입력용**으로 주라인 KDA·딜량 저장
- Champion Mastery API: 상위 숙련도 챔피언
- Summoner `profileIconId`, 모스트 챔피언, 티어 엠블럼은 **Data Dragon 정적 에셋**(D-08)으로 표시
- 전력 = **현재 랭크 티어+구간** (D-03)
- OP / 1~4 **뱃지** 표시 (팀 배정 계산과 무관, D-06)
- 시너지 원 데이터(듀오, 포지션, 챔피언 풀) 수집
- 근거 패널: 티어, LP, 최근 승률, 주 포지션, 모스트 챔피언, 시즌 출처(언랭크 폴백 시)

#### 승률 신뢰도 보정

- 원시 승률이 아니라 판수를 반영한 보정 승률을 사용한다.
- 전체 평균 승률 0.5, 기준 판수 20.

```
adjustedWinRate = (wins + 20 × 0.5) / (games + 20)
```

- 판수가 적을수록 0.5에 가깝고, 많을수록 실제 승률에 가까워진다.

**수용 기준**

- [ ] 참가자 목록에 티어+엠블럼+OP/1~4 뱃지 표시
- [ ] `profileIconId`가 있으면 소환사 프로필 아이콘을 표시하고, 없거나 실패하면 기본 이미지를 표시한다.
- [ ] 모스트 챔피언은 Data Dragon 챔피언 정사각형 아이콘으로 표시된다.
- [ ] 근거 패널에서 산출 근거 확인 가능
- [ ] API 실패 시 해당 참가자만 오류 상태
- [ ] 언랭크·이력 없음 → 수동 티어 입력 UI

**제외 범위**

- 모든 큐 타입 통합 분석

### F-04. 1판 팀 구성 제안 (사전 밸런스)

### F-05. 시험 판 결과 입력 (1~3판)

**목적:** 1·2·3판 결과를 각각 입력하여 **매 판** LP 누적(D-02), **꿀벌 판정·스트릭**(D-07)을 갱신한다.

**입력 방식**

| 방식 | MVP |
|------|-----|
| A. 경기 ID 조회 (Match API) | 필수 |
| B. 수동 입력 (팀 구성 + 승패 + KDA + 딜량) | 필수 |
| C. 점수판 이미지 (OpenAI Vision API) | 필수 |

**요구사항**

- **판 선택 UI:** 1판 / 2판 / 3판 탭 또는 스텝. 이미 입력된 판은 수정 가능
- 각 판: 직전 제안 팀 구성 기본값 + 승리 팀 + (선택) KDA·딜량
- 경기 ID: 참가자 자동 매핑, 불일치 시 수동 매핑. KDA·딜량 자동 수집
- 점수판 이미지: 업로드한 이미지에서 참가자명·KDA·딜량을 추출하고, 직전 제안 팀 또는 등록 참가자와 매핑한다.
- 이미지 추출 결과가 불완전하거나 오인식되면 **수정 가능한 중간 확인 UI**를 제공한다.
- 입력 완료 시 **해당 판** D-02 LP 누적 → `currentLpValue` 갱신
- 입력 완료 시 **해당 판** D-07 꿀벌 판정 → 스트릭·뱃지 갱신 (KDA·딜량 필수)
- **4판 결과 입력 없음** (4판은 F-06 제안·수동 구성만)

**수용 기준**

- [ ] 1·2·3판 각각 입력·수정 가능
- [ ] 점수판 이미지 업로드로 KDA·딜량이 추출되고, 저장 전 사용자 확인·수정이 가능하다.
- [ ] 매 판 LP 70:30 누적 반영
- [ ] KDA·딜량 있을 때 해당 판 꿀벌 판정·스트릭 갱신
- [ ] 3판 입력 후 4판 제안으로 진행 가능 (F-06)
- [ ] 승패만으로도 다음 판 제안 진행 가능 (꿀벌 미판정)

### F-06. 재밸런스 제안 (2·3·4판)

**목적:** 직전 판 결과 반영 **누적 LP**와 D-06 알고리즘으로 **다음 판** 팀을 제안한다.

**대상 판 (`targetRound`)**

| 직전 입력 판 | 제안 대상 |
|--------------|-----------|
| 1판 | 2판 |
| 2판 | 3판 |
| 3판 | **4판** |

**요구사항**

- `targetRound`: 2 | 3 | 4
- 참가자별 **직전 LP → 누적 LP** 반영 티어 표시
- **꿀벌 등급** 뱃지 표시 (D-07 스트릭)
- D-06으로 `targetRound` 팀 제안
- **직전 판 vs 제안 판 비교 뷰:** 이동 인원, 방향, 사유
- 팀 평균 티어·차이·시너지 변화 표시
- 수동 조정 가능 (F-04와 동일 UX)
- `/rebalance?round=4` 등 쿼리로 대상 판 명시 가능

**수용 기준**

- [ ] 1판 후 2판, 2판 후 3판, 3판 후 **4판** 제안 표시
- [ ] 티어 변화·팀 변경·꿀벌 등급·근거 확인 가능
- [ ] 4판은 제안·수동 구성만 (시험 판 입력 UI 없음)

**제외 범위**

- 5판 이상 자동 제안·시험 판 입력

### F-08. AI 분석 문장 (MVP 필수)

**목적:** 팀 제안, 시험 판 결과, 재밸런스 결과를 사람이 빠르게 이해할 수 있도록 **게임 용어 기반의 짧은 AI 요약**을 제공한다.

**모드**

| 모드 | 설명 | 부정적 개인 평가 |
|------|------|------------------|
| `normal` | 기본 모드. 칭찬·중립 위주 요약 | **금지** |
| `friend` | 찐친모드. 더 직설적이고 장난스러운 표현 허용 | **허용** |

**요구사항**

- OpenAI API를 사용해 팀 제안, 시험 판 입력 결과, 재밸런스 결과 요약 문장을 생성한다.
- 입력은 자유 텍스트가 아니라 **구조화된 내부 데이터**를 기반으로 한다.
  - 예: 팀 평균 티어 차이, 이동 인원, 꿀벌 등급, **기대 이상**(`roundHoneyBee`), **기대 이하**(`roundBelowExpect`, D-07)
- 기본값은 `normal` 모드다.
- `normal` 모드에서는 **부정적 개인 평가 문장**을 생성하지 않는다.
  - 기대 이하 플레이어가 있어도, 일반 모드에서는 팀 흐름·재밸런스 포인트·반등 여지 중심으로만 요약한다.
- `friend` 모드는 **명시적 opt-in**일 때만 활성화한다.
- `friend` 모드에서는 `roundBelowExpect === true`(D-07) 플레이어에 대해 범인 후보 마크·장난성 코멘트를 허용할 수 있다.
- 두 모드 모두 욕설, 혐오, 인신공격, 모욕적 표현은 금지한다.
- D-07 꿀벌 판정과 연계해 기대 이상 플레이어는 AI 코멘트에서 우선 강조한다.

**예시 톤**

- `normal`: "A님은 2판 연속 기대 이상으로 반짝이는 꿀벌을 달성했습니다."
- `normal`: "이번 판은 블루 팀의 딜 기여가 고르게 분산됐습니다."
- `friend`: "B님은 이번 판 기대 이하의 모습을 보여 범인 후보로 지목됐습니다."

**수용 기준**

- [ ] F-04/F-05/F-06 화면에서 AI 요약 문장을 볼 수 있다.
- [ ] `normal` 모드에서는 부정적 개인 평가가 생성되지 않는다.
- [ ] `friend` 모드는 사용자가 직접 켠 경우에만 기대 이하/범인성 코멘트를 허용한다.
- [ ] 꿀벌 등급 또는 기대 이상 플레이어가 있을 때 AI 요약에서 우선 반영된다.
- [ ] OpenAI API Key는 클라이언트 번들에 노출되지 않는다.

### F-09. 점수판 이미지 분석 (MVP 필수)

**목적:** 경기 ID가 없거나 수동 입력 부담이 큰 경우, 점수판 이미지를 이용해 시험 판 입력(F-05)을 보조한다.

**요구사항**

- OpenAI Vision API를 사용해 점수판 이미지에서 참가자명, KDA, 딜량을 추출한다.
- 추출된 결과는 **바로 저장하지 않고**, F-05 입력 폼에 채워 넣은 뒤 사용자가 검토·수정 후 확정한다.
- 이미지 분석은 서버 API Route를 통해 수행하며, OpenAI API Key는 서버 환경 변수로만 관리한다.
- 이미지 인식 실패 또는 일부 필드 누락 시에도 수동 보정 경로를 제공한다.
- 이미지 원본 업로드는 판 입력 1회 처리용으로만 사용하며, MVP에서는 별도 영구 저장소를 두지 않는다.

**수용 기준**

- [ ] 점수판 이미지 1장 업로드로 참가자별 KDA·딜량 초안이 생성된다.
- [ ] 사용자는 인식 결과를 수정한 뒤 저장할 수 있다.
- [ ] 인식 실패 시 오류 안내 후 수동 입력으로 이어갈 수 있다.
- [ ] OpenAI API Key는 클라이언트 번들에 노출되지 않는다.

## 5. 화면 구성

```
/                          → 랜딩 (새 내전 / 저장된 세션)
/session/[id]/players      → 참가자 등록 · 전력(티어) 분석
/session/[id]/team         → 1판 팀 제안 (스왑·멤버 추가/제거)
/session/[id]/trial        → 시험 판 결과 입력 (1·2·3판 탭/스텝)
/session/[id]/rebalance    → 재밸런스 (2·3·4판, ?round= 쿼리)
/session/[id]/summary      → AI 요약 보기 (모드: normal / friend)
```

핵심 흐름(전력 분석 → 팀 제안 → 시험 판 → 재밸런스)은 **3클릭 이내** 접근.  
3판 입력 후 4판 제안까지 동일 네비게이션 패턴으로 연속 진행.

## 6. 데이터 모델 (localStorage)

```typescript
Session {
  id: string
  name?: string
  createdAt: string
  participants: Participant[]         // 2~10
  preTeamProposal: TeamProposal       // 1판 제안 (round 1)
  rounds: RoundRecord[]             // length 0~3 (입력된 시험 판)
  commentMode?: 'normal' | 'friend'  // F-08 AI 요약 톤 (기본 normal)
}

RoundRecord {
  round: 1 | 2 | 3                  // 입력된 판
  trialResult: TrialResult
  nextTeamProposal: TeamProposal    // round+1 제안 (2·3·4판)
  lpSnapshotAfterTrial: Record<string, number>  // puuid → 누적 LP
}

Participant {
  riotId: string
  puuid: string
  preTier: TierDisplay                // F-03: "플래티넘 2 · 67LP"
  preLpValue: number                  // 사전 LP (1판 전)
  currentLpValue: number              // 최신 누적 LP (매 판 F-05 후 갱신)
  personalScore: number               // 배정용 (UI 미노출, 재밸런스 전 갱신)
  internalTierBadge: 'OP' | 1 | 2 | 3 | 4   // 뱃지 전용 (1판 전)
  honeyBeeStreak: number              // 연속 꿀벌 판정 횟수
  honeyBeeBadge: 'none' | 'bee' | 'glitterBee' | 'rainbowBee'
  honeyBeeHistory: boolean[]          // [1판, 2판, 3판] 달성 여부
  trialPerformanceByRound?: Record<number, {
    kda: number
    damageDealt: number
    preStatScore: number
    tierExpectScore: number
    trialScore: number
    roundHoneyBee: boolean
    roundBelowExpect: boolean         // D-07, friend 모드·AI 입력용
  }>
  tierSource: 'solo' | 'flex' | 'past_season' | 'manual'
  riotData: {
    tier, lp, winRate, recentStats, masteries, mainRole
    preMainRoleKda?: number                 // D-07 1판 사전 기대치
    preMainRoleDamage?: number
  }
  synergyFactors: { duoPartners, mainRole, topChampions }
}

TeamProposal {
  type: 'pre' | 'rebalance'
  targetRound?: 2 | 3 | 4             // rebalance 시 대상 판
  blueTeam: Participant[]             // length = n/2 (4 or 5)
  redTeam: Participant[]
  blueAvgTier: TierDisplay
  redAvgTier: TierDisplay
  tierDiffDivisions: number
  blueSynergy: 'high' | 'medium' | 'low'
  redSynergy: 'high' | 'medium' | 'low'
  changes?: TeamChange[]              // rebalance only
}

TierDisplay {
  tier: string                        // "PLATINUM"
  rank: string                        // "II"
  lp: number
  label: string                       // "플래티넘 2 · 67LP"
}

TrialResult {
  round: 1 | 2 | 3
  matchId?: string
  winnerTeam: 'blue' | 'red'
  blueTeam: Participant[]
  redTeam: Participant[]
  playerStats: { puuid, kda, damageDealt }[]
}
```

## 7. 외부 API · 비기능 요구

[constitution.md](./constitution.md) 준수.

- MVP 필수: Account, Summoner, League, Match, Champion Mastery, Data Dragon
- MVP 필수: OpenAI Vision (점수판 이미지 분석, F-09)
- MVP 필수: OpenAI 텍스트 요약(F-08)
- MVP 제외: Spectator, RSO
- Riot API는 Next.js API Route(서버) 전용, Key는 환경 변수
- Data Dragon은 Riot 공식 CDN URL을 사용하며, 별도 API Key 없이 조회한다.
- Data Dragon 버전·챔피언 데이터는 캐시하고, 버전 조회 실패 시 fallback 버전을 사용한다.
- OpenAI Vision 호출도 Next.js API Route(서버) 전용으로 수행한다.
- OpenAI 텍스트 요약도 Next.js API Route(서버) 전용으로 수행한다.

| 비기능 | 요구 |
|--------|------|
| 기술 스택 | Next.js, TypeScript, SCSS |
| 반응형 | 모바일·데스크톱 |
| 성능 | 최대 10명 분석 30초 이내 (rate limit 고려) |
| 언어 | 한국어 (MVP) |
