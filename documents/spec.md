## 1. 개요

### 1.1 목적

**8~10명**(짝수)이 참가하는 리그 오브 레전드 내전에서, 플레이어 간 실력 차이를 분석하고 **균형 잡힌 팀 구성**을 제안한다. (8명 → 4:4, 10명 → 5:5)

핵심 가치는 **시험 판 결과를 반영한 다음 판 팀 밸런스 제안**이다. **최대 3판**까지 결과를 입력하고, **2·3·4판**까지 팀을 제안한다. 1판 전에는 공개 데이터 기반 사전 분석을, 각 판 후에는 경기 결과를 **70:30 누적** 반영한다.

### 1.2 대상 사용자

- 친목·동아리·회사 등에서 정기적으로 내전을 진행하는 LoL 플레이어 그룹
- 팀 나누기를 담당하는 **내전 총무**(운영자) 1명
- 별도 계정 가입 없이, Riot ID만으로 참가자를 등록

### 1.3 용어 정의

| 용어 | 정의 |
|------|------|
| **세션** | 한 번의 내전(최대 10명)을 관리하는 단위. localStorage에 저장 |
| **참가자** | 세션에 등록된 플레이어 1명 |
| **전력** | 랭크 티어·최근 경기·숙련도·시험 판 성과를 종합한 실력. **LoL 티어+구간**으로 표현 |
| **개인 점수** | 팀 분배용 내부 점수 (LP 70% · KDA 20% · 승률 10%). UI 노출 안 함 |
| **판 (Round)** | 1~4. 1판=사전 제안, 2~4판=재밸런스 제안. **시험 판 입력은 1~3판만** |
| **내부 티어 (1~5 / OP)** | 세션 상대 등급 (1판 전). **뱃지 표시용**, 팀 전력·배정 계산에 영향 없음 |
| **꿀벌 마크** | 해당 판에서 사전·티어 기대치를 **모두** 초과 시 달성. **연속 스트릭**에 따라 등급 승급 (D-07) |
| **꿀벌 스트릭** | 연속 꿀벌 판정 횟수. 한 판 미달 시 0으로 리셋 |
| **성과 등급 (F~OP)** | 해당 판 기대치 대비 실제 플레이를 6단계(`F·D·C·B·A·OP`)로 표시하는 등급 (D-11). 표시 전용 |
| **평가 불가 (`unrated`)** | 이전 기록·표본이 없어 기대치를 산출할 수 없는 상태. 꿀벌·기대 이하·성과 등급을 **모두 미판정** (D-07) |
| **시너지** | 팀 구성의 질. MVP에서는 **표시·근거만** |
| **시험 판** | 각 판(1~3) 종료 후 입력하는 경기 결과 |
| **재밸런스** | 시험 판 결과 후 **다음 판**(2·3·4판) 팀 구성을 제안하는 기능 |
| **AI 어시스턴트** | 팀·시험·재밸런스 화면 우측에 떠 있는 플로팅 캐릭터. 말풍선으로 AI 요약을 전달 (D-10) |
| **팀 전력 비율** | 두 팀 전력 합을 100으로 정규화한 상대 비율 (예: `블루 51% · 레드 49%`) (D-12) |
| **마무리(종료)** | 내전을 마치고 **총평·평가·피드백**을 남기는 단계 (F-10) |
| **대시보드** | 앱 진입 후 총무 인사·내 플레이어·저장된 세션 목록을 보는 홈 화면 (F-12, D-15) |
| **총무 프로필** | 이 브라우저의 사용자(총무) 정보. 표시 이름·내 플레이어(`myPuuid`)를 localStorage에 저장 (D-15) |
| **세션 상태** | 세션 진행 단계. `preparing`(준비중)·`in_progress`(진행중)·`completed`(완료) (D-15) |
| **모션 시스템** | 단계 전환·콘텐츠 등장·팀 슬라이드 인을 규정하는 애니메이션 규칙 (D-14) |
| **대치 정렬** | 블루팀을 우측 정렬해 레드팀과 마주보게 배치하는 팀 화면 규칙 (D-16) |

## 2. 사용자 시나리오

### 시나리오 A — 사전 분석 후 1판 진행

1. 총무가 세션을 생성한다.
2. 8명 또는 10명의 Riot ID를 등록한다.
3. 앱이 각 참가자의 전력(티어 기준)·내부 티어 뱃지·시너지 요소를 분석·표시한다.
4. 앱이 1판용 팀 구성(블루/레드)을 제안한다.
5. 총무가 제안을 참고·수동 조정한 뒤 1판을 진행한다.

### 시나리오 B — 시험 판 결과 반영·다음 판 재밸런스 (핵심)

1. 1판 종료 → **1판 결과 입력** → LP 누적·꿀벌 판정 → **2판 팀 제안**
2. 2판 진행 후 → **2판 결과 입력** → LP 누적·꿀벌 판정 → **3판 팀 제안**
3. 3판 진행 후 → **3판 결과 입력** → LP 누적·꿀벌 판정 → **4판 팀 제안**
4. (선택) 4판 전 팀 화면에서 **수동** 새 팀 구성

각 단계에서 변경 근거(이동 인원, 티어 변화, 꿀벌 등급, 시너지)를 확인한다.

### 시나리오 C — 시험 판 없이 또는 중간까지

1. 세션 생성 및 참가자 등록
2. 전력·시너지 분석 및 1판 팀 제안만 확인
3. 또는 1~2판까지만 결과 입력 후 종료 가능

### 시나리오 D — 내전 종료·총평 (신규)

1. 원하는 판까지 진행한 뒤 **내전 종료하기**를 누른다.
2. 마무리 페이지에서 이번 세션의 **총합 결과**(판별 승패, 꿀벌 달성, 성과 등급, LP 변화)를 한눈에 본다.
3. (선택) 오늘의 MVP·아쉬운 플레이 등 **평가**를 남기고, 앱 개선 **피드백**을 작성한다.
4. (선택) **개발자 커피 사주기**(후원 안내)를 확인한다.

각 화면에서는 우측 **AI 어시스턴트**가 팀 색·결과·재밸런스에 대한 짧은 요약을 말풍선으로 전달한다.

### 시나리오 E — 대시보드 진입·이어하기 (신규)

1. 앱에 들어오면 랜딩(소개)에서 **시작하기**로 대시보드에 진입한다.
2. 대시보드 상단에서 **"안녕하세요, 총무 {이름}님"** 인사를 본다. (내 플레이어를 지정하면 이름이 채워진다)
3. 저장된 세션이 **그리드 카드**로 보인다 — 각 카드에 **상태(준비중·진행중·완료)**와 **내가 남긴 평점**이 표시된다.
4. 새 내전을 시작하거나, 진행 중 세션을 눌러 이어서 진행한다.

전 화면 전환에는 **모션 시스템**(D-14)이 적용되어, 이전 콘텐츠가 페이드 아웃되고 새 화면이 박스→타이틀→콘텐츠 순으로 등장한다.

## 3. 설계 결정

### D-01. 세션 저장 — **확정: localStorage**

| 항목 | 결정 |
|------|------|
| 저장소 | 브라우저 `localStorage` only |
| 세션 식별 | UUID 기반 `sessionId` |
| 재접속 | 동일 브라우저에서 세션 목록·세션 ID로 재진입 |
| 제한 | 기기·브라우저 변경 시 세션 소실 — MVP에서 허용 |

**수용 기준**

- [ ] 새로고침·탭 재오픈 후에도 세션 데이터가 유지된다.
- [ ] localStorage 용량 초과 시 사용자에게 안내한다.

---

### D-02. 사전 데이터 vs 시험 판 가중치 — **확정: 70:30 (매 판 누적)**

| 단계 | 사전·직전 LP | 시험 판 | 이유 |
|------|-------------|---------|------|
| **1판 팀 제안** | 100% (사전 LP) | 0% | 시험 판 전에는 랭크·최근 지표만 |
| **각 시험 판 후** (1·2·3판) | 70% | 30% | 직전 LP를 주축으로, 해당 판 성과만 보조 반영 |

**내부 계산 방식**

1. 각 참가자의 랭크를 내부 **LP 환산값**으로 변환한다. (예: 골드 2 50LP → 1,550)
2. 주 선호 라인 평균 KDA·보정 승률을 개인 점수 필드에 포함한다. (D-06)
3. **매 시험 판**(1·2·3판) 종료 후, 해당 판 개인 성과를 **기대치 대비 지표**로 환산한다.
   - 기대치: 해당 판 **소속 팀** 내 LP 비율 — LP 조정과 **꿀벌 티어 기대치**(D-07)에 공통 사용
   - **주 지표: KDA + 딜량** (경기 ID 조회 시 Match API)
4. 기대치 대비 초과/미달에 따라 LP 환산값을 **±1~2구간** 범위 내에서 조정한다.
5. **매 판 누적 LP** = `직전 LP × 0.7 + 해당 판 시험 조정 LP × 0.3`
   - 1판 전 `직전 LP` = 사전 LP (`preLpValue`)
   - 2·3판 전 `직전 LP` = 이전 판 누적 후 `currentLpValue`
6. 최종 LP를 **가장 가까운 티어+구간**으로 표시한다 (`currentTier`).

**수동 입력(승패만)일 때**

- KDA·딜량 없으면: 승리 팀 +0.5구간, 패배 팀 −0.5구간 (팀 단위)
- 상세 데이터 있을수록 개인 단위 조정 비중 확대

**수용 기준**

- [ ] 1판 제안 전력은 Riot API 랭크 데이터만 반영한다.
- [ ] 각 시험 판 후 "반영 전 티어 → 반영 후 티어" 변화가 참가자별로 표시된다.
- [ ] 3판까지 LP가 순차 누적된다.
- [ ] 가중치(70:30)·시험 판 지표(KDA+딜량)가 근거 패널(F-07)에 표시된다.

### D-03. 전력 표현 · LP 규칙 — **확정**

| 항목 | 결정 |
|------|------|
| 표시 형식 | `아이언 4` ~ `챌린저` |
| LP | 같은 구간 내 LP 보조 표시 (예: `플래티넘 2 · 67LP`) |
| 팀 전력 | 팀원 LP 환산값 **평균** → 티어로 환산 (예: `팀 평균: 골드 1`) |
| 팀 간 비교 | LP 환산 차이를 구간 단위로 표시 (예: `약 1.2구간 차이`) |

#### 솔로 / 자유 랭크 — **확정: 솔로 우선**

1. **솔로 랭크**가 있으면 솔로 티어·LP를 사용한다.
2. 솔로가 없고 자유 랭크만 있으면 자유 랭크를 사용한다.
3. 둘 다 있으면 **솔로만** 사용한다. (자유는 표시용 보조 정보로만 가능)

#### 언랭크 — **확정: 최근 시즌 티어 → 없으면 수동 입력**

1. 현재 시즌 솔로·자유가 모두 없으면, **과거 시즌 랭크 이력**을 조회한다.
2. **가장 최근 시즌의 티어**를 입력한다. (근거 패널에 "시즌 XX 기준" 표시)
3. 전 시즌 이력이 **아예 없으면** 총무에게 **수동 티어 입력**을 요청한다.
4. 수동 입력 전까지 해당 참가자는 팀 제안에서 **미완료** 상태로 표시한다.

- [ ] Data Dragon 티어 엠블럼과 함께 표시한다.

### D-06. 팀 분배 알고리즘 — **확정**

#### 개인 점수 (Personal Score) — **확정: LP 70% · KDA 20% · 승률 10%**

| 구성 요소 | 가중치 | 데이터 출처 | 정규화 |
|-----------|--------|------------|--------|
| **LP 환산값** | 70% | League API (**솔로 우선**, D-03) | OP 제외 n명 min-max → 0~1 |
| **주라인 KDA** | 20% | Match API (최근 20판, 주 포지션) | OP 제외 n명 min-max → 0~1 |
| **보정 승률** | 10% | F-03 승률 보정 공식 | 이미 0~1 |

```
personalScore =
  normLp(lpValue)       × 0.70
+ normKda(mainRoleKda)  × 0.20
+ adjustedWinRate       × 0.10
```

- `personalScore`는 **팀 배정·라이벌 매칭**에 사용한다.
- UI에는 **LoL 티어**(D-03)만 주 표시. `personalScore`는 노출하지 않는다.
- 2판 이후 재밸런스 시 **누적** `currentLpValue`를 `normLp` 입력으로 사용한다.

#### OP · 내부 1~5티어 — **확정**

**역할 분리**

| 지표 | 용도 | 팀 전력·배정 영향 |
|------|------|-------------------|
| **personalScore** | 라이벌 페어링·팀 배정 계산 | ✅ 사용 |
| **LoL 티어** | 사용자 주 표시·팀 평균 티어 | ✅ 표시 |
| **OP / 1~4 뱃지** | 사람이 한눈에 보는 **상대 등급** (1판 전) | ❌ 영향 없음 |
| **꿀벌 마크** | **매 판** 기대 이상 성과 (1~3판, D-07) | ❌ 영향 없음 |

**OP 판정 — 기본은 1~5티어, OP는 명확한 이상치가 있을 때만**

```
sessionMean = Σ personalScore / n
sessionStdDev = personalScore 표준편차
OP 후보 ⇔ personalScore ≥ max(sessionMean × 1.35, sessionMean + 1.5 × sessionStdDev)
```

- OP 후보가 없으면 전원을 **내부 1~5티어**로 배정한다. 이것이 기본 동작이다.
- 후보가 있을 때만 최고 점수의 명확한 이상치에게 OP를 부여한다. 동일 점수 동률은 복수 OP를 허용하되, 단순히 임계값을 넘은 여러 명에게 OP를 남발하지 않는다.
- OP는 **1~5티어 산출에서 제외**하고 나머지 비OP를 5개 분위로 재분류한다.
- OP도 **라이벌 페어링·팀 배정에는 포함** (8·10명 알고리즘 동일).
- 내부 1~5 / OP는 **뱃지 표시 전용**. 팀 평균 티어·합계·배정 점수에는 쓰지 않는다.

**산출 순서**

1. 전원으로 `personalScore` 산출 (1차, 정규화는 전원 또는 임시)
2. OP 후보 판정(평균 비율 + 표준편차 이중 기준)
3. OP 제외 후 min-max 재정규화 → 최종 `personalScore` (배정용)
4. 비OP만으로 1~5 티어(5분위) 재확립 → 뱃지
5. OP 뱃지 부여 → Step 1 페어링 (전원 포함)

#### 인원 — **확정: 짝수 8·10명, 동일 알고리즘**

| 인원 | 라이벌 페어 | 팀 구성 |
|------|------------|---------|
| 8명 | 4쌍 | 4 vs 4 |
| 10명 | 5쌍 | 5 vs 5 |

- 팀 나누기(F-04)는 **짝수 n ∈ {8, 10}**일 때 동작. 홀수·6명 이하 → 비활성 + 안내.
- 한 팀 목표 전력 = `세션 personalScore 평균 × (n / 2)`.

#### 핵심 알고리즘 (4단계)

**Step 1. 라이벌 페어링**

- `personalScore` 오름차순 정렬 후 **인접 2명씩 페어링** (1–2, 3–4, …).
- 각 플레이어는 정확히 1명의 라이벌.

**Step 2. 팀 배정 — 완전 탐색 (2^k)**

각 페어 `(high, low)`에 대해:

- **선택 A:** high → 블루, low → 레드
- **선택 B:** high → 레드, low → 블루

k쌍 → 2^k 가지 (8명→16, 10명→32). 최적 선택 기준:

1. `|블루 합 − 레드 합|` 최소
2. 동점 → `ideal = sessionMean × n/2`에 더 가까운 쪽
3. 동점 → 라이벌이 서로 다른 팀에 있는 쌍 수 최대

**Step 3. 오프라인 전력 보정 (분석)**

- 주 선호 라인과 다른 포지션일 경우, 해당 라인 전적(KDA·승률)으로 **표시용** 전력 보정.
- Step 2 배정 결과는 **변경하지 않음**.

**Step 4. 근거 출력**

- 라이벌 페어, OP/1~5 뱃지, **꿀벌 등급**, 팀별 합계·ideal 차이, 재밸런스 시 이동 인원·사유.

**제약**

- 블루/레드 각 `n/2`명
- 전력(personalScore) 합계 차이 최소 — Step 2로 보장
- 시너지: 제안 **후** 표시만 (D-04)
- 재밸런스 시 직전 판 대비 변경 인원·이유 산출 (2·3·4판)

### D-07. 꿀벌 마크 — **확정: 시험 판 초과 성과 + 연속 누적 등급**

**1~3판** 각각 시험 판 분석 후, 해당 판에서 **사전 개인 스탯 기대치**와 **티어 기대치**를 **모두** 초과한 참가자에게 그 판 **꿀벌 판정**을 기록한다. OP/1~5와 동일하게 **표시 전용**이며, 팀 배정·LP 조정·personalScore에는 영향 없다.

#### 역할

| 뱃지 | 시점 | 기준 | 배정·전력 영향 |
|------|------|------|----------------|
| OP / 1~4 | 1판 전 (F-03) | 세션 personalScore | 없음 |
| **꿀벌 계열** | 1~3판 각각 (F-05) | 해당 판 사전 스탯 + 티어 기대 초과 | 없음 |

#### 연속 스트릭 · 뱃지 등급

| 연속 꿀벌 판정 | 뱃지 (`honeyBeeBadge`) |
|----------------|------------------------|
| 0회 (미달 또는 리셋) | `none` |
| 1회 연속 | `bee` (꿀벌) |
| 2회 연속 | `glitterBee` (반짝이는 꿀벌) |
| 3회 연속 | `rainbowBee` (무지개 꿀벌) |

- **매 판** D-07 판정 수행. 한 판이라도 미달 → 스트릭 **0 리셋**
- OP + 꿀벌 계열 동시 표시 가능

#### 성과 합산 점수 (내부, UI 미노출)

```
trialScore = normTrialKda × 0.5 + normTrialDamage × 0.5
```

- `normTrialKda`, `normTrialDamage`: **해당 판** 경기 n명 내 min-max (0~1). min = max이면 0.5.

#### 기대치 A — 사전 개인 스탯 (1판만)

- **1판:** F-03 주 포지션 최근 20판 평균 KDA·딜량
- `preStatScore = normPreKda × 0.5 + normPreDamage × 0.5`
- `normPre*`: 세션 참가자 전원 사전 스탯 min-max
- **결측은 0으로 대체하지 않는다.** 사전 스탯이 없는 참가자는 `preStatScore = null`(산출 불가)로 두고, min-max 정규화 **대상에서도 제외**한다. (아래 "기대치 산출 불가")

#### 기대치 A' — 2·3판 (티어 기반 사전 스탯)

- **2·3판:** 기대치 A는 **직전 누적 LP 기반 티어 기대치**와 동일 로직으로 산출한 **개인 기대 KDA·딜량**을 사용 (해당 판 직전 `currentLpValue` 비율)
- 직전 판이 **평가 불가**였더라도, 직전 `currentLpValue`가 있으면 A'는 산출 가능하다.

#### 기대치 B — 티어 기대치 (D-02, 매 판)

- 출처: **해당 판** 소속 팀 내 LP 환산값 비율
- `tierExpectRatio = playerLp / teamLpSum`
- 팀 전체 해당 판 KDA·딜량 합 × 비율 → `tierExpectScore`

#### 기대치 산출 불가 — **평가 제외 (`unrated`)**

기대치를 신뢰할 수 없는 참가자에게 꿀벌·기대 이하·성과 등급을 부여하면 안 된다.  
특히 **이전 기록이 없어 기대치가 0이 되면 어떤 성과든 "기대 초과"가 되어 꿀벌이 남발된다.** 이를 금지한다.

**평가 불가 조건 (하나라도 해당하면 `unrated`)**

| 조건 | 설명 |
|------|------|
| 사전 경기 이력 없음 | 최근 경기 조회 결과가 없음 (신규·휴면 계정, 이력 미공개) |
| 주 포지션 표본 부족 | 주 포지션 경기 수가 최소 표본(**기본 3판**, 조정 가능) 미만 |
| 사전 스탯 결측 | KDA 또는 딜량 중 하나라도 수집되지 않음 |
| 수동 티어만 입력 | 랭크·경기 이력 없이 수동 티어만 있는 경우 (사전 스탯 없음) |
| 기대치 계산 불가 | `preStatScore` 또는 `tierExpectScore`를 수치로 산출할 수 없음 |

**처리 규칙**

- 해당 판 `roundHoneyBee`, `roundBelowExpect`, **성과 등급(D-11)** 을 **모두 미판정**한다. `unrated = true`로 기록한다.
- **기대치 결측을 0(또는 임의 기본값)으로 대체하는 것을 금지**한다.
- 꿀벌 **스트릭은 리셋하지 않고 유지(보류)** 한다. 평가가 이루어지지 않았을 뿐 미달이 아니기 때문이다. 스트릭도 **증가하지 않는다**.
- LP 누적(D-02)은 정상 수행한다. 평가 불가는 **표시 계열에만** 영향을 준다.
- UI·AI 요약에서는 "기록이 부족해 이번 판 평가는 생략했습니다" 같은 **중립 문구**로 표시하고, 미달(F)과 **구분**한다.

**미판정 원인별 스트릭 처리**

| 원인 | 꿀벌 판정 | 스트릭 |
|------|-----------|--------|
| 기대치 산출 불가 (`unrated`, 이전 기록 없음) | 미판정 | **유지** (증가·리셋 없음) |
| 시험 판 KDA·딜량 없음 (승패만 입력) | 미판정 | **0 리셋** (기존 결정 유지) |
| 기대치 미달 | 미달 | **0 리셋** |

#### 꿀벌 판정 (해당 판)

```
// 선행 조건: unrated === false (기대치 A/A'·B가 모두 수치로 산출됨)
roundHoneyBee =
  trialScore > preStatScore   // 1판: F-03 사전 / 2·3판: A'
  AND trialScore > tierExpectScore
```

- **strict greater** (`>`)
- `unrated === true` → 해당 판 꿀벌 **미판정**, 스트릭 **유지**
- KDA·딜량 없음 → 해당 판 꿀벌 **미판정**, 스트릭 리셋

#### 기대 이하 판정 (해당 판, F-08 `friend` 모드용)

꿀벌(기대 이상)과 **동일한 `trialScore`·기대치 A/A'·B**를 사용한다. 판정만 반대다.

```
// 선행 조건: unrated === false
roundBelowExpect =
  trialScore <= preStatScore
  AND trialScore <= tierExpectScore
```

- 꿀벌과 **대칭**: 둘 다 초과 → 기대 이상, **둘 다 이하(또는 동일)** → 기대 이하
- `unrated === true` → 기대 이하 **미판정** (`friend` 모드 범인 후보에서도 제외)
- KDA·딜량 없음 → 기대 이하 **미판정**
- **표시 전용**. 팀 배정·LP·personalScore에 영향 없음
- **일반 모드(`normal`)**에서는 UI·AI 요약에 노출하지 않음
- **찐친모드(`friend`)**에서만 `범인 후보` 마크·직설 코멘트 입력에 사용

#### UI

- LoL 티어·OP/1~5 옆에 꿀벌 아이콘과 **“기대 이상” 텍스트**를 함께 표시한다. 아이콘만 단독 노출하지 않는다.
- F-05 완료 후, F-06, F-07 근거 패널
- 근거 예: "2판 연속 기대 이상 → 반짝이는 꿀벌"
- **평가 불가**: 뱃지 자리에 `—` 또는 `기록 부족` 표시. F 등급·미달과 **다른 시각 처리**를 사용한다.

**수용 기준**

- [ ] 1~3판 각각 KDA+딜량 있을 때 꿀벌 판정·스트릭 갱신
- [ ] 사전 스탯·티어 기대 **둘 다** 초과 시에만 해당 판 달성

### D-08. Data Dragon 정적 에셋 — **확정**

플레이어 프로필 아이콘과 챔피언 이미지는 Riot Games가 공식 제공하는 **Data Dragon CDN**을 사용한다. 티어 엠블럼은 Data Dragon 개별 URL이 존재하지 않으므로 Riot 개발자 포털의 공식 `ranked-emblems-latest.zip` 배포본을 사용한다. 비공식 웹사이트 이미지를 크롤링하지 않는다.

#### 기본 원칙

- Riot API와 Data Dragon을 함께 사용한다.
- Data Dragon 이미지 요청에는 **Riot API Key를 사용하지 않는다**.
- Riot API Key는 서버에서만 사용하며, 클라이언트 코드·Git 저장소에 포함하지 않는다.
- Data Dragon 버전은 화면과 API 코드에 중복 하드코딩하지 않는다.
- 이미지 로딩 실패 시 대체 이미지를 표시한다.
- 프로필·챔피언 이미지와 챔피언 데이터는 앱 전역에서 **동일한 Data Dragon 버전**을 공유한다.

#### 버전 조회 · 캐시 · fallback

- 버전 목록은 `GET https://ddragon.leagueoflegends.com/api/versions.json` 에서 조회한다.
- 응답 배열의 첫 번째 항목을 최신 버전으로 사용한다.
- **매 요청마다 조회하지 않고**, 서버 또는 애플리케이션에서 캐시한다.
- 버전 조회 실패 시 설정된 fallback 버전을 사용한다.

예상 응답:

```json
[
  "16.14.1",
  "16.13.1"
]
```

#### 프로필 아이콘

- Summoner API 응답의 `profileIconId`를 사용한다.
- URL 형식:

```
https://ddragon.leagueoflegends.com/cdn/{version}/img/profileicon/{profileIconId}.png
```

- `profileIconId`가 존재하면 프로필 아이콘을 표시한다.
- `profileIconId`가 없거나 이미지 로딩 실패 시 기본 프로필 이미지를 표시한다.
- 이는 Riot 계정의 업로드 이미지가 아니라 **소환사 프로필 아이콘**이다.

#### 챔피언 데이터 · 매핑

- 한국어 챔피언 목록은 다음 주소에서 조회한다.

```
https://ddragon.leagueoflegends.com/cdn/{version}/data/ko_KR/champion.json
```

- 챔피언 데이터는 요청할 때마다 다시 조회하지 않고 캐시한다.
- Match API의 숫자형 `championId`는 Data Dragon의 문자열 `key`와 매핑한다.
- 절차:
  1. `champion.json`에서 `key === championId` 항목을 찾는다.
  2. 해당 항목의 `id`를 가져온다. 예: `103 -> Ahri`
  3. URL 생성에는 한국어 `name`이나 숫자 `championId`가 아니라 **Data Dragon `id`**를 사용한다.
- 오공처럼 표시 이름과 내부 `id`가 다른 경우를 고려해, **반드시 매핑을 거친다**.

#### 챔피언 이미지 URL

목록, 작은 카드, 전적과 통계 영역에는 정사각형 아이콘을 사용한다.

```
https://ddragon.leagueoflegends.com/cdn/{version}/img/champion/{championDataId}.png
```

큰 카드, 상세 화면, 배경에는 Splash Art를 사용한다.

```
https://ddragon.leagueoflegends.com/cdn/img/champion/splash/{championDataId}_0.jpg
```

세로 비율 이미지가 필요하면 Loading 이미지를 사용한다.

```
https://ddragon.leagueoflegends.com/cdn/img/champion/loading/{championDataId}_0.jpg
```

#### 티어 엠블럼

- Data Dragon CDN은 티어 엠블럼의 개별 이미지 URL을 제공하지 않는다.
- Riot 개발자 포털의 공식 배포본을 사용한다:
  `https://static.developer.riotgames.com/docs/lol/ranked-emblems-latest.zip`
- 표시용 `Rank={Tier}.png` 파일만 `public/ranked-emblems`에 포함하고, 비공식 CommunityDragon URL은 사용하지 않는다.
- `tierEmblemUrl(tier)` 유틸로 로컬 정적 URL을 생성하며, 지원하지 않는 티어는 `null`로 처리한다.

#### 제외 범위

- 스킨 이미지는 현재 MVP 범위에서 제외한다.
- 추후 스킨 기능을 구현할 때만 개별 챔피언 JSON의 `skins[].num`을 사용한다.
- 이미지 존재 여부를 확인하지 않고 스킨 URL을 임의 생성하지 않는다.

#### 권장 타입

```ts
type ChampionSummary = {
  id: string;
  key: string;
  name: string;
  title: string;
  image: {
    full: string;
  };
};

type DataDragonImageUrls = {
  square: string;
  splash: string;
  loading: string;
};
```

**수용 기준**

- [ ] 프로필·챔피언은 Data Dragon 공식 CDN, 티어 엠블럼은 Riot 공식 배포본만 사용하고 비공식 이미지 크롤링을 하지 않는다.
- [ ] `versions.json` 실패 시 fallback 버전으로 일관된 URL을 생성한다.
- [ ] 앱 전역에서 이미지와 챔피언 데이터가 동일한 Data Dragon 버전을 사용한다.
- [ ] `championId`는 매핑 후 Data Dragon `id`로 이미지 URL을 생성한다.
- [ ] 프로필 아이콘·챔피언 이미지 로딩 실패 시 대체 이미지가 표시된다.

### D-09. Riot ID 검색 UX — **확정: debounce + 계정 목록 선택**

Riot Account API는 **exact match**만 지원한다. 자동완성·부분 일치 검색 API는 없으므로, MVP는 아래 규칙으로 검색 UX를 제공한다.

#### 동작

1. 참가자 등록 입력란에 게임명 또는 `게임명#태그`를 입력한다.
2. 입력이 **400ms** 동안 멈추면(debounce) 서버 검색 API를 호출한다.
3. 검색 결과를 입력란 아래 **계정 목록**으로 표시한다.
4. 목록 항목을 클릭하면 해당 Riot ID로 참가자 등록·전력 분석 파이프라인(F-03)을 실행한다.
5. Enter 키 또는 **참가자 추가** 버튼으로도 현재 입력값을 직접 등록할 수 있다.

#### 검색 규칙

| 입력 형태 | API 동작 | 결과 |
|-----------|----------|------|
| 2자 미만 | 검색 안 함 | — |
| `게임명`만 (태그 없음) | KR 태그 후보 `KR1`~`KR5` 순차 조회 | 0~5건 목록 |
| `게임명#태그` (태그 2자 이상) | 해당 Riot ID 1건 exact 조회 | 0~1건 목록 |
| `게임명#` 또는 태그 1자 | 검색 안 함 | 입력 중 안내 |

- 이미 세션에 등록된 계정은 목록에서 제외한다.
- Rate limit을 고려해 태그 후보 조회는 **순차**로 수행한다(서버 `riotFetch` 간격 유지).
- 검색 API Key는 서버 전용이며, 클라이언트에 노출하지 않는다.

**수용 기준**

- [ ] 입력 후 debounce로 자동 검색이 실행된다.
- [ ] 검색 결과 목록에서 클릭 한 번으로 참가자를 등록할 수 있다.
- [ ] 결과 없음·로딩·오류 상태가 구분되어 표시된다.
- [ ] exact match API 제약이 문서·UI helper에 반영된다.

> 근거: feedback.md — "무료 API인 gemini 모델로 변경". Gemini는 멀티모달이므로 Vision까지 하나의 제공자·키로 통합해 관리 비용을 줄인다.

#### 전달 방식 — **독립 페이지 삭제 → 플로팅 진입 버튼 + 우측 사이드바**

1. 독립 `/session/[id]/summary` 페이지를 **삭제**한다.
2. **팀 제안·시험 판·재밸런스·마무리** 화면 우측 하단에 원형 플로팅 진입 버튼을 배치한다.
3. 버튼을 클릭하면 화면 오른쪽에서 **AI 사이드바**가 열린다. 데스크톱에서는 본문을 가리지 않도록 폭을 확보하고, 모바일에서는 전체 화면 drawer로 전환한다.
4. 첫 응답에는 현재 화면 맥락(팀 색·결과·재밸런스)에 대한 요약과 **주목할 플레이어 1~2명**을 함께 제안한다. `unrated` 참가자는 성과 기반 주목 선수에서 제외한다.
5. 응답 아래에 맥락별 **예시 질문 3개**를 표시한다. 사용자는 예시를 클릭하거나 직접 후속 질문을 입력해 같은 세션 맥락으로 재질문할 수 있다.
6. 대화 기록은 현재 사이드바 세션 동안 유지하되 새로고침 후 영구 보존하지 않는다. 서버에는 전체 원본 세션이 아니라 필요한 구조화 데이터와 최근 대화만 전송한다.
7. `normal` / `friend` 모드 토글은 사이드바 헤더에 둔다(기본 `normal`).

**수용 기준**

- [ ] `/summary` 독립 페이지가 없고, 플로팅 버튼으로 우측 AI 사이드바를 연다.

### D-11. 성과 등급 — **확정: F·D·C·B·A·OP (기대치 대비, 표시 전용)**

꿀벌(기대 이상)·기대 이하(D-07)의 이분 판정만으로는 재밸런스 화면에서 개인 플레이를 직관적으로 보기 어렵다는 피드백을 반영해, **해당 판 기대치 대비 성과를 6단계 등급**으로 표시한다.

#### 산출

- D-07의 `trialScore`와 **기대치**(사전 스탯 A/A' 및 티어 기대 B의 대표값, 기본은 두 기대치의 평균)를 사용한다.
- 성과 비율 `r = trialScore / expectScore` (expectScore = `(preStatScore + tierExpectScore) / 2`).

| 등급 | 비율 `r` (기본 임계값, 조정 가능) | 의미 |
|------|-----------------------------------|------|
| **OP** | `r ≥ 1.50` | 압도적 초과 성과 |
| **A** | `1.20 ≤ r < 1.50` | 기대 크게 상회 |
| **B** | `1.00 ≤ r < 1.20` | 기대 상회 (꿀벌 판정 경계) |
| **C** | `0.85 ≤ r < 1.00` | 기대 수준 |
| **D** | `0.60 ≤ r < 0.85` | 기대 미달 |
| **F** | `r < 0.60` | 기대 크게 미달 |

- 정확한 임계값은 구현 상수([implementation-plan.md](./implementation-plan.md))에서 관리한다.
- **표시 전용.** 팀 배정·LP 조정·`personalScore`·꿀벌 판정에 영향을 주지 않는다.
- 꿀벌/기대 이하 판정과 **모순되지 않게** 매핑한다 (OP·A는 기대 이상, F·D는 기대 이하 계열).
- KDA·딜량이 없으면(승패만 입력) 성과 등급 **미표시**.
- **기대치를 산출할 수 없으면(D-07 `unrated`, 이전 기록 없음) 등급을 부여하지 않는다.** 기대치를 0으로 대체해 OP를 주는 동작을 금지한다.

#### UI

- 재밸런스 화면 팀원 카드와 시험 판 결과에 등급 뱃지 표시.
- 근거 패널: "이번 판 딜·KDA가 기대치의 1.3배 → A 등급" 같은 게임 용어.
- 평가 불가(`unrated`)는 등급 뱃지 자리에 `—` / `기록 부족`을 표시하고, **F 등급과 구분**한다.

**수용 기준**

- [ ] 시험 판 입력(KDA·딜량) 후 참가자별 F~OP 등급이 산출된다.
- [ ] 등급이 꿀벌/기대 이하 판정과 모순되지 않는다.
- [ ] 승패만 입력 시 등급 미표시.
- [ ] 이전 기록이 없어 기대치를 못 구하면 등급이 부여되지 않고 `기록 부족`으로 표시된다.
- [ ] 등급이 팀 배정·LP·개인 점수를 변경하지 않는다.

### D-12. 팀 전력 표시 — **확정: 가독성 기본 + 100분위 비율 + 팀별 첨부**

팀 컬럼의 **블루/레드 구분·가독성**은 2차 반복의 꾸밈이 아니라 **MVP 기본 요구**다.  
1차에서 팀 영역이 눈에 안 띄던 것은 미충족이었고, 재구현에서도 동일하게 충족해야 한다.  
2차에서 **새로 추가**되는 것은 전력 **100분위 상대 비율**과 평균 티어의 **헤더 첨부**다.

#### 기본 요구 — 팀 구분·가독성 (항상)

- 블루/레드 컬럼은 **한눈에 팀 소속이 구분**되어야 한다 (팀 색 틴트·헤더·라벨 등).
- 목적은 **가독성**이다. 장식용으로 과도한 그라디언트·글로우·애니메이션을 쓰지 않는다.
- Hextech Glass 토큰 범위 안에서 팀 색을 적용하되, **텍스트·뱃지 대비**를 해치지 않는다.
- 팀 제안(F-04)·재밸런스(F-06) 모두 동일 기준을 적용한다.

#### 2차 추가 — 전력 비율

- 두 팀의 전력 합(`Σ personalScore`, 재밸런스 시 누적 LP 기반)을 **합이 100이 되도록 정규화**한다.
- 예: 블루 합 512, 레드 합 488 → `블루 51% · 레드 49%`.
- 반올림으로 두 값의 합이 100이 되도록 보정한다.
- 전력 비율 막대(51/49)를 두 팀 사이 또는 각 팀 헤더에 표시한다.
- 전력 비율은 **표시 전용**이며 배정 알고리즘(D-06)을 바꾸지 않는다.

#### 2차 추가 — 평균 티어 헤더 첨부

- **팀별 평균 티어**(`blueAvgTier` / `redAvgTier`)를 각 팀 컬럼 **헤더에 첨부**한다 (하단 요약에만 두지 않음).

**수용 기준**

- [ ] 팀 제안·재밸런스에서 블루/레드가 **가독성 있게** 구분된다 (장식 과다 없이).
- [ ] 각 팀 헤더에 평균 티어가 붙어 표시된다.
- [ ] 두 팀 전력이 합 100의 상대 비율(예: 51% vs 49%)로 표시된다.

### D-13. 주 라인 표시 — **확정: 텍스트 대신 라인 아이콘**

주 포지션(주 라인)을 `정글`, `미드` 같은 **텍스트**로 표기하면 카드가 산만해지고 한눈에 읽히지 않는다. **라인 아이콘**을 기본 표시로 사용한다.

#### 라인 구분

Match API `teamPosition` 값을 5개 라인으로 매핑한다.

| API 값 | 라인 | 한국어 라벨 |
|--------|------|-------------|
| `TOP` | 탑 | 탑 |
| `JUNGLE` | 정글 | 정글 |
| `MIDDLE` | 미드 | 미드 |
| `BOTTOM` | 바텀 | 원딜 |
| `UTILITY` | 유틸리티 | 서포터 |
| (없음·불명) | — | 미확인 |

#### 에셋 규칙

- 라인 아이콘은 **프로젝트 자체 인라인 SVG 컴포넌트**로 제공한다.
- Data Dragon은 라인 아이콘을 공식 제공하지 않는다. 따라서 **Riot 클라이언트 에셋을 복제하거나 비공식 CDN을 크롤링하지 않는다** (D-08 원칙 동일 적용).
- 아이콘은 단색 기반으로, 팀 색·상태 색과 충돌하지 않게 토큰 색을 사용한다.
- 라인 미확인 시 **중립 placeholder 아이콘**을 표시한다.

#### 표시·접근성

- 표시 위치: 참가자 카드, 팀 제안·재밸런스 팀원, 시험 판 입력 행, 근거 패널.
- 아이콘에는 **`aria-label`(또는 시각적으로 숨긴 텍스트)** 로 한국어 라인명을 제공한다.
- hover / focus 시 **툴팁으로 라인명**을 노출한다.
- 아이콘만으로 의미를 전달하는 곳이라도, 근거 패널·상세 뷰에서는 텍스트 라인명을 함께 확인할 수 있어야 한다.

**수용 기준**

- [ ] 주 라인이 텍스트가 아닌 라인 아이콘으로 표시된다.
- [ ] 5개 라인 각각 구분되는 아이콘이 있고, 미확인 시 placeholder가 표시된다.
- [ ] 아이콘에 접근성 라벨과 툴팁 라인명이 제공된다.
- [ ] 비공식 라인 아이콘 에셋을 크롤링·복제하지 않는다.

### D-14. 모션·애니메이션 시스템 — **확정: 단계 전환 + 순차 등장 + 팀 슬라이드 인**

1차·2차 결과물은 기능은 되지만 **정적·딱딱한 인상**이었다. 3차에서는 화면 전환과 콘텐츠 등장에 일관된 모션 규칙을 적용해 자연스러운 흐름을 만든다. 단, 모션은 **정보 가독성과 성능을 해치지 않는 선**에서만 사용한다.

#### 이징·지속시간

- 기본 이징은 **`ease-in-out` 계열 cubic-bezier**를 적극 사용한다 (예: `cubic-bezier(0.4, 0, 0.2, 1)`). 선형(linear)·급격한 곡선은 지양한다.
- 진입/퇴장 등 콘텐츠 전환은 **220~420ms** 범위를 사용한다 (기존 hover 마이크로 인터랙션 150~250ms는 유지).
- 순차 등장(stagger)은 항목당 **40~80ms** 지연을 누적한다.

#### 단계 전환 (페이지/스텝 이동)

- 다음 단계로 넘어갈 때 **현재 화면의 모든 박스는 페이드 아웃**된다.
- 새 화면은 항상 **박스(컨테이너) → 타이틀 → 리스트/주요 콘텐츠** 순서로 등장한다 (위계적 순차 등장).
- 등장 모션은 페이드 + 소폭 상방 이동(`translateY`) 조합을 기본으로 한다.

#### 팀별 방향성 슬라이드 인

- **참가자 등록을 제외한** 모든 플레이어 카드는 팀 방향으로 슬라이드 인한다.
  - **블루팀:** 좌 → 우 (`translateX(-)` → 0)
  - **레드팀:** 우 → 좌 (`translateX(+)` → 0)
- 같은 팀 카드는 순차 지연(stagger)으로 등장한다.

#### 강조 모션 (예외)

- 팀 제안 CTA(팀 제안하기 버튼)는 **활성화 시 그라디언트 애니메이션**으로 강조한다 (F-02). 이는 의도된 예외이며, 무한 루프라도 저강도로 제한한다.

#### 접근성

- `prefers-reduced-motion: reduce`에서는 이동/슬라이드/그라디언트 루프를 생략하고, 즉시 표시하거나 최소한의 페이드만 사용한다.
- 모션은 콘텐츠 접근을 지연시키지 않는다 (키보드·스크린리더 흐름은 모션과 무관하게 즉시 동작).

**수용 기준**

- [ ] 단계 전환 시 이전 박스가 페이드 아웃되고, 새 화면이 박스→타이틀→콘텐츠 순으로 등장한다.
- [ ] 플레이어 카드가 블루 좌→우 / 레드 우→좌로 슬라이드 인한다 (등록 화면 제외).
- [ ] 팀 제안 CTA가 활성화되면 그라디언트 애니메이션으로 강조된다.
- [ ] `prefers-reduced-motion`에서 이동·루프 모션이 생략된다.

### D-15. 대시보드 · 총무 프로필 — **확정: 홈 화면 + 내 플레이어 + 세션 상태·평점**

랜딩에서 곧장 세션 생성만 하던 흐름 대신, 앱의 **홈 = 대시보드**를 둔다. 총무 개인화(인사·내 플레이어)와 저장된 세션의 상태·평점을 한눈에 제공한다.

#### 총무 프로필 (localStorage)

- 이 브라우저 사용자를 **총무 프로필**로 관리한다: 표시 이름, Riot ID, 내 플레이어(`myPuuid`).
- **내 정보 추가:** 대시보드에서 Riot ID를 검색하고 검색 결과 계정을 선택해 "나"로 지정한다. 특정 세션의 참가자가 먼저 존재할 필요는 없다.
- 지정한 계정이 세션 참가자와 같은 PUUID이면 시험 판 최근 경기 조회의 기본 플레이어로 사용한다(F-05).
- 미지정 시 인사말은 일반 문구("안녕하세요, 총무님")로 대체한다.
- 서버 계정·인증은 없으며 프로필은 localStorage에만 저장한다.

#### 세션 상태

- 각 세션은 상태를 가진다: `preparing`(참가자 등록 이전/미완), `in_progress`(1판 제안~진행 중), `completed`(마무리 `wrapUp` 존재).
- 상태는 세션 데이터에서 파생한다: 팀 제안 전 `preparing`, 팀 제안 이후 `in_progress`, `wrapUp` 존재 시 `completed`. 표시는 상태 칩으로 한다.

#### 세션 그리드

- 저장된 세션을 **그리드 카드**로 나열한다. 각 카드: 세션명·생성일·**상태 칩**·**내 평점**(F-10 별점, 있으면).
- 카드 클릭 시 해당 세션의 적절한 단계로 재진입한다.

**수용 기준**

- [ ] 대시보드 상단에 "안녕하세요, 총무 {이름}님" 인사가 표시된다 (미지정 시 일반 문구).
- [ ] 대시보드 Riot ID 검색 결과에서 내 플레이어를 지정/해제할 수 있다.
- [ ] 저장된 세션이 그리드 카드로 표시되고, 각 카드에 상태와 내 평점이 보인다.
- [ ] 카드에서 세션을 이어서 진행할 수 있다.

### D-16. 팀 대치 정렬 — **확정: 블루팀 우측 정렬로 대치 강조**

블루/레드가 나란히 좌측 정렬되면 "대전" 느낌이 약하다. 팀 화면(제안·재밸런스·게임 결과)에서 **블루팀을 우측 정렬**해 두 팀이 마주보는 **대치 구도**를 만든다.

- 컬럼 위치는 기존대로 **좌측 블루팀 / 우측 레드팀**을 유지한다.
- **블루팀(좌측 컬럼):** 팀 박스 헤더·타이틀·팀원 카드 내용 **우측 정렬**해 중앙을 향하게 한다.
- **레드팀(우측 컬럼):** 좌측 정렬해 중앙을 향하게 한다.
- 두 팀 컬럼은 화면 중앙을 기준으로 마주본다.
- **카드 폭:** 대치 정렬은 **콘텐츠 정렬만** 바꾼다. 팀원 카드는 두 팀 모두 **팀 박스 안쪽 폭 100%**를 채우며, 정렬 때문에 카드가 내용 폭으로 줄어들지 않는다.
- **요소 순서 미러링:** 블루팀 카드는 레드팀 카드의 **좌우 거울 배치**를 따른다. 프로필 이미지·챔피언·티어 엠블럼뿐 아니라 **카드 내 뱃지 행(내부 티어 뱃지·라인 아이콘·성과·뱃지)도 순서를 반대로** 배치해, 두 팀 모두 중앙에서 바깥쪽으로 같은 순서로 읽히게 한다.
- 대치 정렬은 표시 규칙이며 팀 배정 로직(D-06)·데이터에는 영향이 없다.
- 모바일 등 컬럼이 세로로 쌓일 때는 정렬·순서 미러링을 모두 해제하고 가독성을 우선한다.

**수용 기준**

- [ ] 팀 제안·재밸런스·게임 결과에서 좌측 블루/우측 레드 컬럼 위치를 유지하고 두 팀 내용이 중앙을 향한다.
- [ ] 블루 박스 헤더·타이틀·팀원 카드 내용이 우측 기준으로 정렬된다.
- [ ] 블루·레드 팀원 카드가 모두 팀 박스 안쪽 폭 100%로 표시된다.
- [ ] 블루팀 카드의 티어 뱃지·라인 아이콘 순서가 레드팀과 반대로(거울) 표시된다.
- [ ] 모바일 1열에서는 블루팀도 좌측 정렬·기본 순서로 돌아간다.
- [ ] 대치 정렬이 팀 배정 결과를 바꾸지 않는다.

### D-17. 스크롤·전역 스타일 구조 — **확정: 숨김 스크롤바 + 전역 SCSS 클래스**

- 페이지 스크롤 동작과 키보드·휠·터치 탐색은 유지하되 시각적 스크롤바만 숨긴다. `overflow: hidden`으로 스크롤 자체를 막지 않는다.
- 기존 Hextech Glass 토큰·SCSS 시각 스타일은 유지한다.
- 4차 구현은 `*.module.scss`와 `styles.foo` 바인딩을 사용하지 않는다. `styles/globals.scss`에서 화면별 SCSS partial을 불러오고, 전역 클래스는 충돌 방지를 위해 `tg-` 접두사와 BEM 형태(`tg-team-card__badges`)를 사용한다.
- 컴포넌트는 문자열 클래스명만 사용하며 상태는 `is-active`, `is-blue`, `is-red`처럼 명시한다.

### D-18. 분석 전환 화면 — **확정: 결과 전 2~3초 분석 모션**

- 팀 제안 생성, 시험 판 저장 후 재밸런스 계산처럼 결과가 크게 바뀌는 전환에는 2~3초의 분석 화면을 표시한다.
- 단계 문구와 작은 모션을 순차 표시한다(예: `전력 비교 중 → 역할 조합 확인 중 → 팀 제안 완성`).
- 분석 중 중복 제출을 차단하며 실제 계산/API 실패를 고정 타이머로 숨기지 않는다. 계산이 실패하면 즉시 오류와 재시도 경로를 제공한다.
- `prefers-reduced-motion`에서는 모션을 제거하지만 최소한의 진행 상태 문구는 유지한다.

### D-19. 참가자 재사용 검색 — **확정: 정확한 Riot ID + 로컬 최근 등록 목록**

- Riot Account API는 게임명만으로 부분 검색할 수 없으므로 원격 조회에는 정확한 `게임명#태그`가 필요하다. 태그가 없을 때 임의로 `#KR1`을 붙이지 않는다.
- 검색창에 게임명만 입력하면 localStorage의 **이전에 등록한 플레이어 목록**에서 게임명을 부분 일치해 후보를 보여준다.
- 검색창 옆 `이전 플레이어` 버튼으로 최근 등록 목록 모달을 열고 계정 재등록·목록 삭제를 지원한다.
- 로컬 후보가 없으면 `#태그까지 입력해 주세요` 안내와 입력 예시를 표시한다.

### D-20. 결과 공개 퍼포먼스 — **확정: 순차 인트로 후 전체 결과**

- 마무리 진입 시 `세션 인트로 → 최종 승리팀 → MVP → 기대 이상 플레이어`를 한 단계씩 공개한다.
- 각 단계는 **후킹 → (~0.8~1.2초 드럼롤) → 본체 공개 → 보조 콘텐츠 → CTA 페이드인** 비트로 진행한다. “다음”/“건너뛰기”는 본체 공개가 끝난 뒤에만 노출한다.
- 사용자는 CTA 노출 후 클릭/키보드(Enter·→)로 다음 단계로 진행할 수 있고 `건너뛰기`로 즉시 전체 결과에 진입할 수 있다.
- **Stage 0:** 「내전이 종료되었습니다! 결과를 확인 해 볼까요!」 → ~1초 후 세션명 페이드업 → 진행 판 수 → CTA
- **Stage 1:** 「그렇다면… 최종 승리 팀은?」 → 드럼롤 → `{팀명|블루팀/레드팀} 승리` + 승리팀 컬러 wash + 팀원 아이콘·이름 배너(최대 5) → CTA
- **Stage 2:** 「이번 내전의 MVP는…」 → 드럼롤 → MVP 아이콘·이름 히어로 + KDA·피해량 보조 문구 → CTA. 선정 불가 시 짧은 드럼롤 후 「선정할 기록이 부족합니다」
- **Stage 3:** 「기대를 뛰어넘은 플레이어는…」 → 드럼롤 → 최다 꿀벌 배너(공동 1위 전원) + 보조 문구 → 「전체 결과 보기」. 0회면 드럼롤 없이 「해당 없음」
- `prefers-reduced-motion`에서는 연출을 생략하고 단계 내용·CTA를 즉시 표시한다.
- 최종 승리팀에는 팀 이름이 있으면 팀 이름을 우선 표시하고 팀원 프로필 아이콘·Riot ID를 배너로 함께 보여준다.
- 자동 MVP는 전체 경기의 킬·데스·어시스트와 챔피언 피해량을 정규화한 종합 기여도로 1명을 선정한다.
- `이번 내전의 꿀벌(기대 이상)`은 `roundHoneyBee` 횟수가 가장 많은 참가자이며 공동 1위는 모두 표시한다. 0회면 해당 없음으로 표시한다.
- 티어가 오른 참가자는 블루 계열, 내려간 참가자는 레드 계열로 강조한다. feedback의 “내려간 사람도 파란색”은 의미상 대비가 사라지므로 **하락=레드**로 해석하며 다음 구현 전 변경 가능하다.

### D-21. 개발자 이스터에그 태그 — **확정: 표시 전용 · 하드코딩 레지스트리**

특정 플레이어에게 **재미용 태그·이펙트**를 붙일 수 있다. **점수·팀 배정·꿀벌·성과 등급·AI 주목 선수 선정과 무관**하다.

#### 규칙

| 항목 | 결정 |
|------|------|
| 매칭 키 | **PUUID 우선**. Riot ID(`게임명#태그`)는 닉네임 변경으로 깨질 수 있어 보조 키로만 둔다 |
| 효과 범위 | 플레이어 카드 UI만 (등록·팀·시험·재밸런스·마무리) |
| 점수 영향 | **없음**. `personalScore`, OP, 배정, LP, 꿀벌, F~OP에 전달 금지 |
| 관리 방식 | 서버/DB 없이 클라이언트 상수 파일에 하드코딩 |
| 접근성 | 태그 텍스트는 스크린리더에 노출. 모션은 `prefers-reduced-motion`에서 제거 |

#### 하드코딩 예시 (구현 시 이 파일을 채우면 됨)

경로 권장: `lib/constants/easterEggs.ts`

```ts
export type EasterEggEffect = "none" | "glow" | "rainbow" | "sparkle";

export interface EasterEggTag {
  /** 권장: Riot PUUID (닉 변경에 안전) */
  puuid?: string;
  /** 보조: "게임명#태그" — 대소문자 무시 비교 */
  riotId?: string;
  /** 카드에 붙는 짧은 라벨 */
  label: string;
  /** 선택 이모지/아이콘 힌트 */
  emoji?: string;
  /** CSS 이펙트 키 → .tg-easter-egg--{effect} */
  effect?: EasterEggEffect;
  /** 툴팁/aria에 쓸 한 줄 설명 */
  note?: string;
}

/**
 * 개발자가 직접 채운다. 점수/배정 로직은 이 배열을 import하지 않는다.
 * 카드 렌더에서만 lookupEasterEgg(puuid, riotId)로 조회한다.
 */
export const EASTER_EGG_TAGS: EasterEggTag[] = [
  // 예시 — 실제 값으로 교체
  {
    puuid: "REPLACE_WITH_REAL_PUUID",
    riotId: "숨은고수#KR1",
    label: "개발자의 친구",
    emoji: "✨",
    effect: "sparkle",
    note: "재미용 태그. 전력 분석과 무관합니다.",
  },
  {
    riotId: "내전총무#DEV",
    label: "앱 제작자",
    emoji: "🛠️",
    effect: "glow",
    note: "이 앱을 만든 사람입니다.",
  },
];
```

조회 예시:

```ts
export function lookupEasterEgg(
  puuid?: string,
  riotId?: string,
): EasterEggTag | undefined {
  const id = riotId?.trim().toLowerCase();
  return EASTER_EGG_TAGS.find((egg) =>
    (puuid && egg.puuid === puuid) ||
    (id && egg.riotId?.toLowerCase() === id),
  );
}
```

**수용 기준**

- [ ] 레지스트리에 있는 플레이어 카드에만 태그/이펙트가 표시된다.
- [ ] 태그가 있어도 `personalScore`·팀 배정·꿀벌·성과 등급·AI 주목 선수 결과가 바뀌지 않는다.
- [ ] 도메인 로직·요약 페이로드가 `EASTER_EGG_TAGS`를 import하지 않는다.
- [ ] `prefers-reduced-motion`에서 이펙트 모션이 꺼지고 라벨 텍스트는 남는다.

### F-12. 대시보드 (신규)

**목적:** 앱 홈에서 총무 개인화와 저장된 세션 관리를 제공한다 (D-15).

**요구사항**

**수용 기준**

- [ ] 카드에서 세션 재진입, 새 내전 생성이 가능하다

- 서버 동기화, 여러 총무 프로필/전환 (MVP 제외)

### F-02. 참가자 등록 (Riot ID)

**목적:** 최대 10명의 참가자를 세션에 등록한다.

**요구사항**

- `게임명#태그` 형식 입력, Account API로 PUUID 조회. Riot 원격 API는 부분 검색을 지원하지 않으므로 태그 없는 입력을 임의의 `#KR1`로 조회하지 않는다.
- **debounce 검색 + 계정 목록 선택** (D-09, D-19): 정확한 Riot ID는 원격 조회하고, 태그 없는 게임명은 로컬 최근 등록 목록을 부분 검색한다.
- **원격 검색 후보 미리보기:** 정확한 `게임명#태그` 조회가 성공하면 등록 전에 **소환사 프로필 아이콘과 대표 티어(솔로 우선, 없으면 자유랭크, 모두 없으면 언랭크)**를 후보 카드에 표시한다.
- `이전 플레이어` 버튼과 모달을 제공해 이 브라우저에서 등록한 계정을 다시 선택하거나 기록에서 삭제할 수 있다.
- 검색 결과 목록은 **로딩 → 목록 → 선택** 흐름이 뚜렷해야 한다 (feedback: 검색창 개선)
- 최소 2명, 최대 10명 (팀 제안: **짝수 8 또는 10명**)
- 중복 등록 불가
- 유효하지 않은 ID → 명확한 오류 메시지
- 검색·등록한 플레이어를 localStorage에 저장
- **8·10명 준비 완료** 시 인원 배지(`n/10 · 팀 제안하기`)와 본문 CTA로 `/team`에 바로 이동 가능

#### 등록 목록 표시 (feedback 반영 · v3.0 개정)

- 팀원 추가 단계에서는 상세 전력 정보를 펼치기보다, **지금 어떤 계정을 추가했는지 한눈에** 볼 수 있는 **간략 카드**(닉네임#태그 + 프로필 아이콘 + 대표 티어)를 기본으로 한다.
- **모든 등록 플레이어가 등록과 동시에 한 화면에 보이도록** 배치한다 (스크롤로 숨지 않게).
  - **안내 문구는 박스에 넣지 않고**, 검색창 **상단의 작은 텍스트**로 표시한다 (본캐 경고 등).
  - 등록 카드 **크기를 약 50% 축소**하고, **좌 5명 / 우 5명 2열**로 배치한다. **왼쪽 열을 먼저 채우고** 다음에 오른쪽 열을 채운다 (좌열 → 우열 순차).
  - 상세 전력·근거는 **아코디언이 아니라, 카드 hover 시 뜨는 플로팅 모달(HoverCard)**로 제공한다.
- 입력란 상단에 **"부캐라면 본캐 계정을 입력하세요"** 안내 문구를 작은 텍스트로 상시 노출한다.
- **팀 제안하기 CTA**는 준비 완료(8·10명) 시 **그라디언트 애니메이션**으로 강조한다 (D-14).
- 참가자 카드 자체는 등록 화면이므로 팀 방향 슬라이드 인(D-14) 대상에서 제외한다.

**수용 기준**

- [ ] 유효 ID → 참가자 **간략 카드** 추가
- [ ] 무효 ID → 오류 표시
- [ ] 입력 debounce 후 로딩·계정 목록·선택 상태가 구분되어 표시된다
- [ ] 원격 검색 후보 카드에 소환사 아이콘과 대표 티어가 표시되고, 언랭크는 수동 티어 입력 필요 상태로 구분된다
- [ ] 태그 없는 입력은 로컬 최근 등록 후보를 보여주고, 후보가 없으면 `#태그` 입력 안내를 표시한다
- [ ] 이전 플레이어 모달에서 과거 등록 계정을 재등록·삭제할 수 있다
- [ ] 등록된 플레이어가 좌5/우5 2열로, 좌열→우열 순서로 채워지며 한 화면에 보인다
- [ ] 안내 문구가 박스가 아닌 검색창 상단 소형 텍스트로 표시된다
- [ ] 카드 상세가 hover 플로팅 모달로 표시된다 (아코디언 아님)
- [ ] "부캐라면 본캐 계정을 입력하세요" 경고 문구가 표시된다
- [ ] 8·10명 미만 시 팀 제안 불가 상태 표시
- [ ] 8·10명 준비 완료 시 팀 제안 CTA가 그라디언트 애니메이션으로 강조되고 팀 제안 화면으로 이동 가능

**제외 범위**

- RSO 로그인, 본인 인증

### F-03. 참가자 전력 분석 (사전)

**목적:** 시험 판 이전, 공개 데이터로 각 참가자 전력을 **LoL 티어**로 표시한다.

**요구사항**

- League API: **솔로 우선** 티어·LP·승률 (D-03). 언랭크 시 최근 시즌 → 수동 입력
- Match API: 최근 20판 요약 (KDA, CS, 피해량, 시야, 주 포지션) — **꿀벌 마크 사전 기대치(D-07) 입력용**으로 주라인 KDA·딜량 저장
  - 주 포지션 **경기 수**(`preMainRoleGames`)도 함께 저장한다. 표본이 최소치(기본 3판) 미만이거나 스탯이 결측이면 **기대치 산출 불가(`unrated`)** 로 표시하고, **0으로 대체하지 않는다** (D-07)
- 주 라인은 **라인 아이콘**으로 표시한다 (D-13). 텍스트 라인명은 접근성 라벨·툴팁·근거 패널에서 제공
- Champion Mastery API: 상위 숙련도 챔피언
- Summoner `profileIconId`, 모스트 챔피언, 티어 엠블럼은 **Data Dragon 정적 에셋**(D-08)으로 표시
- 전력 = **현재 랭크 티어+구간** (D-03)
- OP / 1~4 **뱃지** 표시 (팀 배정 계산과 무관, D-06)
- 시너지 원 데이터(듀오, 포지션, 챔피언 풀) 수집
- 근거 패널: 티어, LP, 최근 승률, 주 포지션, 모스트 챔피언, 시즌 출처(언랭크 폴백 시)

#### 승률 신뢰도 보정

- 원시 승률이 아니라 판수를 반영한 보정 승률을 사용한다.
- 전체 평균 승률 0.5, 기준 판수 20.

```
adjustedWinRate = (wins + 20 × 0.5) / (games + 20)
```

- 판수가 적을수록 0.5에 가깝고, 많을수록 실제 승률에 가까워진다.

**수용 기준**

- [ ] 참가자 목록에 티어+엠블럼+OP/1~5 뱃지 표시
- [ ] 주 라인이 라인 아이콘으로 표시된다 (D-13)
- [ ] `profileIconId`가 있으면 소환사 프로필 아이콘을 표시하고, 없거나 실패하면 기본 이미지를 표시한다.
- [ ] 모스트 챔피언은 Data Dragon 챔피언 정사각형 아이콘으로 표시된다.
- [ ] 근거 패널에서 산출 근거 확인 가능
- [ ] API 실패 시 해당 참가자만 오류 상태
- [ ] 언랭크·이력 없음 → 수동 티어 입력 UI

### F-04. 1판 팀 구성 제안 (사전 밸런스)

**목적:** 사전 전력(100%)으로 1판용 4:4 또는 5:5 팀을 제안한다. 총무는 제안을 참고하되 **자유롭게 팀을 구성**할 수 있다.

**요구사항**

- D-06 팀 분배 알고리즘 적용
- 블루/레드 `n/2` vs `n/2` 카드 UI
- **블루 VS 레드 가독성** (D-12 기본): 팀 색으로 컬럼을 분명히 구분한다. 화려함보다 **읽기 쉬운 대비**를 우선한다
- **대치 정렬** (D-16): 블루팀은 헤더·타이틀·팀원 카드를 **우측 정렬**하고 카드 내 요소 순서를 **거울 배치**해 레드팀과 마주보는 대치 구도를 만든다. 카드는 두 팀 모두 팀 박스 안쪽 폭 **100%**를 채운다
- 팀원 카드는 등장 시 **팀 방향 슬라이드 인**(블루 좌→우, 레드 우→좌, D-14)
- 각 팀 **이름 바로 옆에 평균 티어 첨부** (`블루팀 · 평균 골드 2` / `레드팀 · 평균 골드 1`)
- **팀 전력 100분위 비율** 표시 (예: `51% vs 49%`, D-12 2차 추가)
- **티어 차이(구간)**, **시너지 등급**, OP/1~5 뱃지 표시
- **밸런스 근거는 팀 제안 박스 우측 상단의 "밸런스 근거 보기" 아이콘**으로 제공하고, **hover 시 상세 근거 박스를 플로팅**으로 노출한다 (상시 큰 패널로 자리를 차지하지 않음)
- **선수 추가/교체는 각 팀 박스의 버튼**으로 제공한다. 클릭 시 **블루팀이면 좌측, 레드팀이면 우측**에 **미니 플레이어 추가 모달**을 플로팅으로 띄운다
- **시험 판으로 넘어가는 버튼은 팀 분석 하단의 버튼 리스트 구역**에 배치한다 (팀 박스 안이 아니라 하단 액션 구역)
- 제안 생성 직후 결과를 즉시 바꾸지 않고 D-18의 2~3초 분석 전환 화면을 거쳐 공개한다.
- 우측 **AI 어시스턴트**가 팀 색·밸런스에 대한 코멘트를 말풍선으로 제공 (D-10, F-08)
- 총무 **수동 스왑** 가능, 조정 시 지표(평균·비율·시너지) 실시간 갱신
- **1판 팀 화면에서 즉시** 팀원 제거·새 멤버 등록 가능 (등록 화면으로 강제 이동하지 않음)
- 수동 구성 완료 후 그대로 1판 진행 가능 (알고리즘 제안 강제 아님)

**수용 기준**

- [ ] 8명·10명 등록 시 4:4 / 5:5 제안
- [ ] 블루/레드가 가독성 있게 구분되고, 블루팀이 우측 정렬·거울 순서로 대치된다 (D-16)
- [ ] 팀원 카드가 팀 박스 안쪽 폭 100%로 채워진다 (D-16)
- [ ] 팀원 카드가 팀 방향으로 슬라이드 인한다 (D-14)
- [ ] 각 팀 헤더에 평균 티어가 붙고, 전력 비율(예: 51% vs 49%)이 표시된다
- [ ] 밸런스 근거가 우상단 아이콘 hover 플로팅으로 표시된다
- [ ] 선수 추가/교체 버튼이 각 팀 박스에 있고, 블루는 좌·레드는 우로 미니 모달이 뜬다
- [ ] 시험 판 진행 버튼이 팀 분석 하단 버튼 구역에 있다
- [ ] 수동 스왑 시 지표 즉시 반영
- [ ] AI 어시스턴트 말풍선으로 팀 색 코멘트를 볼 수 있다
- [ ] 팀원 빼기·멤버 새로 등록이 1판 화면에서 즉시 가능

**제외 범위**

### F-05. 시험 판 결과 입력 (1~3판)

**목적:** 1·2·3판 결과를 각각 입력하여 **매 판** LP 누적(D-02), **꿀벌 판정·스트릭**(D-07)을 갱신한다.

**입력 방식**

| 방식 | MVP |
|------|-----|
| A. 경기 ID 조회 (Match API) | 필수 |
| A'. **참가자 최근 경기 목록에서 선택** (Match API) | 필수 (보조 모달) |
| B. 수동 입력 (팀 구성 + 승패 + KDA + 딜량) | 필수 |
| C. 점수판 이미지 (Gemini 멀티모달, F-09) | 필수 (보조 모달) |

**요구사항**

- **판 선택 UI:** 1판 / 2판 / 3판 탭 또는 스텝. 이미 입력된 판은 수정 가능
  - 판 선택 탭은 **화면 우측 상단에 고정**한다 (feedback: 1·2·3판 박스 우상단 고정)
- 시험 결과 입력 폼은 팀 제안의 대치 정렬을 재사용하지 않고 **블루·레드 모두 좌측 정렬**로 고정한다. 입력 정확성과 필드 스캔을 우선한다.
- 승리 팀 선택은 토글 버튼으로 제공하고, 선택된 버튼 전체 배경을 블루/레드 팀 컬러로 채운다.
- 참가자별 KDA·피해량과 함께 **플레이한 챔피언** 및 **실제 플레이 라인**을 입력한다. 경기 ID·최근 경기·이미지 보조 입력이 제공하는 값도 수정 가능해야 한다.
- 각 판: 직전 제안 팀 구성 기본값 + 승리 팀 + (선택) KDA·딜량
- **기본 입력은 수동(팀 구성·승패·KDA·딜량)**이며, 경기 ID·최근 경기 선택·이미지는 **보조 수단**이다.
  - 보조 수단은 폼을 가리지 않는 **작은 보조 버튼**으로 노출하고, 클릭 시 **모달**에서 처리한다.
  - 모달에서 추출·매핑을 끝내면 결과를 **메인 폼에 채워 넣고** 닫는다.
- 경기 ID(모달): 참가자 자동 매핑, 불일치 시 수동 매핑. KDA·딜량 자동 수집
- **최근 경기 선택(모달):** 총무 프로필의 내 플레이어가 현재 세션 참가자이면 해당 플레이어의 최근 경기 목록을 우선 불러온다. 내 플레이어가 없거나 현재 세션 참가자가 아니면 총무가 이 판 참가자 **한 명을 선택**한다. 선택된 플레이어의 최근 경기 목록(Match API)에서 **해당 내전 경기**를 고르면 팀 구성·승패·KDA·딜량을 자동으로 폼에 채운다.
  - 불러온 경기 참가자와 세션 참가자를 매핑하고, 불일치 시 수동 매핑을 지원한다.
- 점수판 이미지(모달): 업로드 이미지에서 참가자명·KDA·딜량을 추출하고 직전 제안 팀 또는 등록 참가자와 매핑한다. 추출 결과가 불완전·오인식이면 **수정 가능한 중간 확인 UI**를 제공한다.
- **내전 종료 진입:** 시험 판 화면에서 **4판 전이라도 "내전 종료하기" 버튼을 상시 제공**해 언제든 마무리(F-10)로 갈 수 있다.
- **KDA·딜량 placeholder 개선:** 어떤 형식으로 채우는지 알 수 있게 예시를 표시한다 (예: KDA `3.5` 또는 `12/4/9`, 딜량 `20,170`).
- 수동 KDA·딜량 입력은 **쉼표 천단위·소수점** 표기를 허용한다 (예: `20,170`, `1.50`).
- **폼 상태 유지:** 입력값은 `setState`로 관리해, 탭 전환·모달 열기·재렌더 시에도 값이 **날아가지 않게** 한다. (feedback: 저장 안 하면 자꾸 날려먹음)
- 입력 완료 시 **해당 판** D-02 LP 누적 → `currentLpValue` 갱신
- 입력 완료 시 **해당 판** D-07 꿀벌 판정·D-11 성과 등급 → 스트릭·뱃지·등급 갱신 (KDA·딜량 필수)
- **이전 기록이 없어 기대치를 산출할 수 없는 참가자**는 꿀벌·기대 이하·성과 등급을 **미판정**(`unrated`)하고, LP 누적만 수행한다 (D-07)
- **4판 결과 입력 없음** (4판은 F-06 제안·수동 구성만)
- 저장 후 재밸런스 화면으로 이동하기 전에 D-18의 2~3초 분석 전환 화면을 표시한다.

**수용 기준**

- [ ] 1·2·3판 각각 입력·수정 가능, 판 선택 탭이 우측 상단에 고정된다
- [ ] 양 팀 입력 행이 좌측 정렬로 표시된다
- [ ] 선택한 승리 팀 토글의 버튼 배경 전체가 해당 팀 컬러로 표시된다
- [ ] 참가자별 챔피언·실제 플레이 라인을 입력·수정할 수 있다
- [ ] 보조 입력(경기 ID·최근 경기 선택·이미지)이 작은 버튼 + 모달로 제공되고, 결과가 메인 폼에 채워진다
- [ ] 참가자 최근 경기 목록에서 경기를 선택하면 팀 구성·승패·KDA·딜량이 자동으로 채워진다
- [ ] 4판 전에도 "내전 종료하기" 버튼으로 마무리 화면에 진입할 수 있다
- [ ] 점수판 이미지 업로드로 KDA·딜량이 추출되고, 저장 전 사용자 확인·수정이 가능하다
- [ ] KDA·딜량 입력란에 형식 예시 placeholder가 표시된다
- [ ] `20,170` / `1.50` 형식 수동 입력이 정상 파싱된다
- [ ] 탭 전환·모달 열기·재렌더 후에도 입력값이 유지된다
- [ ] 매 판 LP 70:30 누적 반영
- [ ] KDA·딜량 있을 때 해당 판 꿀벌 판정·성과 등급·스트릭 갱신
- [ ] 이전 기록이 없는 참가자는 꿀벌·등급 미판정이고 스트릭이 유지된다
- [ ] 3판 입력 후 4판 제안으로 진행 가능 (F-06)
- [ ] 승패만으로도 다음 판 제안 진행 가능 (꿀벌·등급 미판정)

### F-06. 재밸런스 제안 (2·3·4판)

**목적:** 직전 판 결과 반영 **누적 LP**와 D-06 알고리즘으로 **다음 판** 팀을 제안한다.

**대상 판 (`targetRound`)**

| 직전 입력 판 | 제안 대상 |
|--------------|-----------|
| 1판 | 2판 |
| 2판 | 3판 |
| 3판 | **4판** |

**요구사항**

- `targetRound`: 2 | 3 | 4
- **팀 중심 표시** (feedback): 이동 인원 목록보다, 제안된 **블루/레드 팀**을 먼저 크게 보여준다 (D-12 가독성 구분·평균 티어·전력 비율 동일 적용)
- **대치 정렬** (D-16): 블루팀 우측 정렬. 블루 카드 프로필 아이콘은 우측, 레드 카드 프로필 아이콘은 좌측에 두며 블루 카드의 칩 행은 `justify-content: flex-end`로 정렬한다. 팀원 카드는 팀 방향 슬라이드 인(D-14)
- 각 팀원 카드에 **직전 LP → 누적 LP** 반영 티어와 **직전 판 성과 등급(F·D·C·B·A·OP, D-11)** 표시
- **꿀벌 등급** 뱃지 표시 (D-07 스트릭)
- **트레이드 표시 (강조):** 직전 판 대비 교체된 팀원을 `플레이어A ↔ 플레이어G` 형태로 명시하고, 제안 팀 목록에서도 **교체된 팀원 카드에 border 강조**를 준다. 강조된 카드는 **누가 어느 팀에서 왔는지(들어온/나간)** 를 함께 표시한다.
- **전판 대비 개인 점수 증감:** 참가자별 상승 `▲n%` / 하강 `▼n%`를 표시 (게임 용어 기준, 내부 점수 자체는 노출하지 않음)
- D-06으로 `targetRound` 팀 제안
- 우측 **AI 어시스턴트**가 재밸런스 변화(이동·색·기대치)를 말풍선으로 요약 (D-10)
- 팀 평균 티어·차이·시너지 변화 표시
- 수동 조정 가능 (F-04와 동일 UX)
- `/rebalance?round=4` 등 쿼리로 대상 판 명시 가능

**수용 기준**

- [ ] 1판 후 2판, 2판 후 3판, 3판 후 **4판** 제안 표시
- [ ] 팀 중심 UI로 블루/레드 팀·평균 티어·전력 비율이 먼저 보인다 (블루 우측 정렬)
- [ ] 팀원별 직전 판 성과 등급(F~OP)이 표시된다
- [ ] 교체 팀원이 `A ↔ G` 형태로 표시되고 카드 border로 강조되며, 들어온/나간 팀원이 누구인지 표시된다
- [ ] 참가자별 전판 대비 개인 점수 증감(▲/▼ n%)이 표시된다
- [ ] 티어 변화·꿀벌 등급·근거 확인 가능
- [ ] 4판은 제안·수동 구성만 (시험 판 입력 UI 없음)

**제외 범위**

- 5판 이상 자동 제안·시험 판 입력

### F-08. AI 분석 문장 · 플로팅 어시스턴트 (MVP 필수)

**목적:** 팀 제안, 시험 판 결과, 재밸런스 결과를 사람이 빠르게 이해하고 후속 질문까지 이어갈 수 있도록 **게임 용어 기반 AI 사이드바 챗봇**(D-10)을 제공한다.

**모드**

| 모드 | 설명 | 부정적 개인 평가 |
|------|------|------------------|
| `normal` | 기본 모드. 칭찬·중립 위주 요약 | **금지** |
| `friend` | 찐친모드. 더 직설적이고 장난스러운 표현 허용 | **허용** |

**요구사항**

- **Google Gemini API**(D-10)를 사용해 팀 제안, 시험 판 입력 결과, 재밸런스 결과 요약 문장을 생성한다.
- **전달 방식(D-10):** 독립 요약 페이지 없이 원형 플로팅 버튼으로 우측 사이드바를 연다. 최초 요약 뒤 예시 질문 3개와 직접 질문 입력을 제공한다.
- 팀 제안 화면에서는 **팀 색(블루/레드) 코멘트**를 포함한다 (feedback: AI 분석 팀 컬러 멘트).
- 입력은 자유 텍스트가 아니라 **구조화된 내부 데이터**를 기반으로 한다.
  - 예: 팀 평균 티어 차이, 전력 비율(D-12), 이동 인원, 꿀벌 등급, 성과 등급(D-11), **기대 이상**(`roundHoneyBee`), **기대 이하**(`roundBelowExpect`, D-07)
- 기본값은 `normal` 모드이며, 모드 토글은 어시스턴트 말풍선 내부에 둔다.
- `normal` 모드에서는 **부정적 개인 평가 문장**을 생성하지 않는다.
  - 기대 이하 플레이어가 있어도, 일반 모드에서는 팀 흐름·재밸런스 포인트·반등 여지 중심으로만 요약한다.
- `friend` 모드는 **명시적 opt-in**일 때만 활성화한다.
- `friend` 모드에서는 `roundBelowExpect === true`(D-07) 플레이어에 대해 범인 후보 마크·장난성 코멘트를 허용할 수 있다.
- 두 모드 모두 욕설, 혐오, 인신공격, 모욕적 표현은 금지한다.
- D-07 꿀벌 판정과 연계해 기대 이상 플레이어는 AI 코멘트에서 우선 강조한다.
- 최초 요약마다 구조화 데이터에 근거해 **주목할 플레이어 1~2명**을 선정하고 선정 이유를 함께 표시한다. 기록이 충분한 기대 이상·고기여 참가자를 우선하며, 억지로 2명을 채우지 않는다.
- **평가 불가(`unrated`, 이전 기록 없음) 참가자**는 기대 이상/이하 코멘트·범인 후보 대상에서 **제외**하고, 필요 시 "기록이 부족해 평가를 생략했다"는 중립 문구만 사용한다.

**예시 톤**

- `normal`: "블루 팀 전력이 51%로 근소하게 앞섭니다. 딜 기여가 고르게 분산됐어요."
- `normal`: "A님은 2판 연속 기대 이상으로 반짝이는 꿀벌을 달성했습니다."
- `friend`: "B님은 이번 판 기대 이하의 모습을 보여 범인 후보로 지목됐습니다."

**수용 기준**

- [ ] F-04/F-05/F-06/F-10 화면에서 플로팅 버튼으로 AI 사이드바를 열 수 있다.
- [ ] 최초 요약에 주목할 플레이어 1~2명과 이유가 표시된다.
- [ ] 예시 질문 3개를 선택하거나 직접 후속 질문을 입력할 수 있다.
- [ ] 팀 제안 화면 요약에 팀 색 코멘트가 포함된다.
- [ ] `normal` 모드에서는 부정적 개인 평가가 생성되지 않는다.
- [ ] `friend` 모드는 사용자가 직접 켠 경우에만 기대 이하/범인성 코멘트를 허용한다.
- [ ] 꿀벌 등급 또는 기대 이상 플레이어가 있을 때 AI 요약에서 우선 반영된다.
- [ ] Gemini API Key는 클라이언트 번들에 노출되지 않는다.

### F-09. 점수판 이미지 분석 (MVP 필수)

**목적:** 경기 ID가 없거나 수동 입력 부담이 큰 경우, 점수판 이미지를 이용해 시험 판 입력(F-05)을 보조한다.

**요구사항**

- **Google Gemini 멀티모달 API**(D-10)로 점수판 이미지에서 참가자명, KDA, 딜량을 추출한다.
- 추출은 F-05 **보조 모달** 안에서 수행하며, 결과는 **바로 저장하지 않고** 검토·수정 후 메인 입력 폼에 채워 넣는다.
- 이미지 분석은 서버 API Route를 통해 수행하며, Gemini API Key는 서버 환경 변수로만 관리한다.
- 이미지 인식 실패 또는 일부 필드 누락 시에도 수동 보정 경로를 제공한다.
- 이미지 원본 업로드는 판 입력 1회 처리용으로만 사용하며, MVP에서는 별도 영구 저장소를 두지 않는다.

**수용 기준**

- [ ] 점수판 이미지 1장 업로드로 참가자별 KDA·딜량 초안이 생성된다.
- [ ] 사용자는 인식 결과를 수정한 뒤 저장할 수 있다.
- [ ] 인식 실패 시 오류 안내 후 수동 입력으로 이어갈 수 있다.
- [ ] Gemini API Key는 클라이언트 번들에 노출되지 않는다.

### F-10. 내전 종료 · 마무리 (신규)

**목적:** 내전을 마치고 이번 세션의 **총합 결과**를 확인하고, **평가**와 **피드백**을 남긴다. (feedback: 마무리 페이지)

**진입**

- 팀·시험·재밸런스 화면에서 **"내전 종료하기"** 액션으로 진입한다.
- 몇 판까지 진행했든(1~4판) 종료할 수 있다.

**요구사항 — 결과 공개 인트로(D-20)**

- 마무리 진입 시 전체 결과를 즉시 한 번에 노출하지 않고 세션 인트로 → 최종 승리팀 → MVP → 이번 내전의 꿀벌 순으로 **두구두구→짜잔** 비트(후킹·드럼롤·본체·CTA)로 공개한다.
- 최종 승리팀 단계에는 팀 이름(있으면)·승리팀 컬러 wash·팀원 아이콘+이름 배너(최대 5)를 표시한다.
- MVP는 전체 판 킬·데스·어시스트·피해량 종합 기여도로 자동 선정하며 히어로(아이콘+이름)로 공개한다.
- 이번 내전의 꿀벌은 `roundHoneyBee` 최다 횟수 기준이며 공동 1위는 모두 배너로 표시한다.
- CTA는 본체 공개 후에만 나타나며, `건너뛰기` 및 `prefers-reduced-motion`(연출 생략·내용·CTA 즉시) 대응을 제공한다. 인트로가 끝나면 전체 총합 결과를 보여준다.

**요구사항 — 총합 결과**

- **최종 승리팀 강조:** 진행한 판의 **최다 승 팀**을 최종 승리팀으로 명시한다. 각 경기는 무승부가 없으며, 세션 승수가 동률인 경우 마지막 진행 판 승리팀을 타이브레이커로 사용한다. 마무리 화면의 **가장 큰 대표 박스를 해당 팀 컬러**(블루/레드)로 표시한다.
- 판별 요약: 각 판 승리 팀(블루/레드)을 **컬러 강조 칩**으로 표시하고, 참가자 성과 등급(F~OP), 꿀벌 달성 여부를 함께 보여준다.
- 참가자별 **사전 티어 → 최종 누적 티어** 변화와 개인 점수 증감 추이. 티어 상승 카드는 블루, 하락 카드는 레드, 변화 없음은 중립으로 강조한다.
- 세션 하이라이트: 최고 성과(꿀벌 스트릭·OP 등급), 전체 판 수, MVP 후보
- AI 어시스턴트(F-08)의 세션 총평 말풍선(모드에 따름)

**요구사항 — 평가 · 피드백**

- (선택) 오늘의 **MVP·아쉬운 플레이** 등 사용자 평가 입력
- (선택) 앱 개선 **피드백** 텍스트 입력
- **성과 별점(1~5):** 세션 성과에 대한 별점 하나를 제공한다. 피드백은 별점 없이 텍스트만 입력한다. 성과 별점은 세션 `wrapUp`에 저장하고, **대시보드 카드의 "내 평점"**(F-12)으로 노출한다.
- 평가·피드백·성과 별점은 localStorage 세션에 저장한다 (MVP; 서버 전송 없음)

**수용 기준**

- [ ] 진행한 판까지의 총합 결과가 한 화면에 요약된다.
- [ ] 결과 인트로가 세션명 → 승리팀 → MVP → 꿀벌 순으로 진행되고 건너뛸 수 있다.
- [ ] 승리팀 팀원 아이콘, 자동 MVP, 공동 1위 포함 꿀벌 최다 참가자가 정확히 표시된다.
- [ ] 최종 승리팀이 명시되고 대표 박스가 해당 팀 컬러로 강조된다.
- [ ] 판별 결과가 팀 컬러 강조 칩으로 표시된다.
- [ ] 참가자별 티어 변화·성과·꿀벌이 표시된다.
- [ ] 티어 상승은 블루, 하락은 레드, 동일은 중립 컬러로 구분된다.
- [ ] 성과 별점(1~5)·평가·텍스트 피드백을 입력하고 저장할 수 있으며, 성과 별점이 대시보드 카드에 반영된다.
- [ ] 어떤 판 수에서 종료해도 마무리 화면이 동작한다.

**제외 범위**

- 서버 전송·집계, 결과 공유 링크 (MVP 제외)

### F-11. 개발자 후원 (커피 사주기)

**목적:** 앱을 무료로 제공하되, 원하는 사용자가 개발자를 후원할 수 있는 안내를 제공한다. (feedback: 개발자 커피 사주기)

**요구사항**

- 후원 수단(계좌번호·카카오페이/토스 링크 등)을 표시한다. 구체 값은 설정/상수로 관리한다.
- 계좌번호는 **복사 버튼**을 제공한다.

**수용 기준**

- [ ] 마무리 화면에서 후원 안내를 볼 수 있다.
- [ ] 계좌번호 복사 또는 후원 링크 이동이 가능하다.
- [ ] 후원 영역이 핵심 흐름을 가리지 않는다.

**제외 범위**

- 실제 결제 연동, 후원 집계 (MVP 제외)

## 5. 화면 구성

```
/                          → 랜딩 (소개 · 고정 상단 배너/중앙 로고 → 시작하기)
/dashboard                 → 대시보드 (총무 인사 · 내 플레이어 · 세션 그리드)  [신규 F-12]
/session/[id]/players      → 참가자 등록 · 전력(티어) 분석
/session/[id]/team         → 1판 팀 제안 (스왑·멤버 추가/제거)
/session/[id]/trial        → 시험 판 결과 입력 (1·2·3판 탭/스텝, 보조 모달)
/session/[id]/rebalance    → 재밸런스 (2·3·4판, ?round= 쿼리)
/session/[id]/finish       → 내전 종료·마무리 (총합 결과·평가·별점·피드백·후원)
```

- 랜딩은 **소개형**이며, 세션 목록·생성은 **대시보드(`/dashboard`, F-12)**에서 한다.
- **AI 요약 전용 페이지(`/summary`)는 삭제**한다. AI 요약은 team·trial·rebalance·finish 화면의 **플로팅 어시스턴트**(D-10, F-08)로 제공한다.
- 상단 **고정 배너(중앙 로고)**는 공통 크롬으로 유지한다 (D-14, design-system TopBanner).
- 모든 화면 전환·콘텐츠 등장에 **모션 시스템(D-14)**을 적용한다.
- 핵심 흐름(대시보드 → 전력 분석 → 팀 제안 → 시험 판 → 재밸런스 → 종료)은 **3클릭 이내** 접근.
- 3판 입력 후 4판 제안까지 동일 네비게이션 패턴으로 연속 진행.

## 7. 외부 API · 비기능 요구

[constitution.md](./constitution.md) 준수.

- MVP 필수: Account, Summoner, League, Match, Champion Mastery, Data Dragon
- MVP 필수: **Google Gemini** 텍스트 요약(F-08) + 점수판 이미지 분석(F-09) — 멀티모달 단일 제공자 (D-10)
- MVP 제외: Spectator, RSO
- Riot API는 Next.js API Route(서버) 전용, Key는 환경 변수
- Data Dragon은 Riot 공식 CDN URL을 사용하며, 별도 API Key 없이 조회한다.
- Data Dragon 버전·챔피언 데이터는 캐시하고, 버전 조회 실패 시 fallback 버전을 사용한다.
- Gemini 텍스트 요약·이미지 분석 호출은 모두 Next.js API Route(서버) 전용으로 수행하며, `GEMINI_API_KEY`는 서버 환경 변수로만 관리한다.
- 이전 `OPENAI_API_KEY`는 더 이상 사용하지 않으며 env 템플릿에서 제거한다.

| 비기능 | 요구 |

| 반응형 | 모바일·데스크톱 |
| 성능 | 최대 10명 분석 30초 이내 (rate limit 고려) |
| 언어 | 한국어 (MVP) |
