# 리그오브레전드 내전 팀 구성 시뮬레이터 '내전 총무' 웹 어플리케이션 헌법 정의

## 배경 지식

- 이 프로젝트는 SDD(Spec-driven Development) 방식으로 구현된다.
- 헌법정의 -> 기능명세 -> 구현계획 -> 작업정의 -> 구현 의 단계를 따르며, 추후 테스트에 대한 코드를 추가할 수 있다.


## 이 앱의 목적

- 라이엇사의 온라인게임 '리그오브레전드'의 플레이어들이 자체적으로 5대5 내전을 진행하게 될 경우 생기는 모호한 실력차를 분석, 각 팀의 전력을 분석하여 팀 구성에 쓰이는 어려움을 완화한다.
- 이미 한번의 시험 게임을 진행하였다면, 해당 게임 결과를 기반으로 각 팀의 전력을 비등하게 만들 수 있는 두번째 팀 벨런스를 제시한다. 이것이 아주 큰 컨셉이다.

## principle

---------

### 사용자 중심

- 사용자는 별도의 설명 없이 어플리케이션의 핵심 기능인 전력 분석 기능을 사용할 수 있어야한다.
- 내부 기술 구조를 사용자에게 노출하지 않는다. 이는 로직적인 부분에서만 포함된다
- 분석에 사용한 근거와 논리는 사용자가 납득할 수 있어야 하며, 투명성이 보장되어야한다.

### 필요한 것만 구현한다

- 명세에 없는 기능을 임의로 추가하지 않는다.
- 미래의 확장 가능성만을 이유로 구조를 복잡하게 만들지 않는다.
- 추상화는 실제로 두 번 이상 반복되는 문제를 확인한 후 도입한다.


### 명세가 구현의 기준이다

- 기능 구현 전에 목적, 요구사항, 제외 범위와 수용 기준을 정의한다.
- 구현과 명세가 충돌하면 임의로 코드를 변경하지 않고 차이를 보고한다.
- 요구사항 변경은 명세에 먼저 반영한다.
이유:
AI와 개발자가 같은 목표를 기준으로 작업하기 위해서다.

### 작업은 작고 추적 가능해야한다.

- 하나에 Task에는 하나의 명확한 목적만 둔다.
- Task마다 완료 조건과 검증 방법을 작성한다.
- 서로 독립적인 Task에는 병렬 실행 가능 여부를 표시한다.
- 요구사항과 관계없는 리팩터링을 함께 수행하지 않는다.


이유:
작업 범위를 통제하고 구현 실패의 원인을 쉽게 추적하기 위해서다.

### 기술 스택
- 만약 명세된 기능 구현을 위해 새로운 워크프레임 혹은 API가 필요할 경우 개발자에게 보고한다

### 기술 스택
- NEXT.js
- Typescript
- Scss

#### 외부 API

| API | 용도 | 필수 여부 |
|---|---|---|
| Riot Account API (`ACCOUNT-V1`) | Riot ID와 태그로 사용자 검색, PUUID 조회 | 필수 |
| Riot Summoner API (`SUMMONER-V4`) | 소환사 기본 정보, 소환사 ID 조회 | 필수 |
| Riot League API (`LEAGUE-V4`) | 티어, 랭크, LP, 랭크 승·패 조회 | 필수 |
| Riot Match API (`MATCH-V5`) | 최근 경기 목록 및 KDA, CS, 피해량, 시야 점수 등 경기 상세 데이터 조회 | 필수 |
| Riot Champion Mastery API (`CHAMPION-MASTERY-V4`) | 챔피언 숙련도, 모스트 챔피언 조회 | 필수 |
| Riot Spectator API (`SPECTATOR-V5`) | 현재 진행 중인 게임과 참가자 정보 조회 | 선택 |
| Riot Sign On (`RSO`) | Riot 계정 로그인 및 사용자 데이터 제공 동의 처리 | 선택 |
| Riot Data Dragon | 챔피언, 아이템, 룬 정보와 이미지 조회 | 필수 |
| OpenAI API | 팀 컬러, 주요 전력, 승리·패배 요인 등 AI 분석 문장 생성 | 선택 |
| OpenAI Vision API | 업로드된 점수판 이미지 판독 및 경기 결과 분석 | 선택 |

Riot API는 서버에서 호출해야 하며 API Key를 프런트엔드 코드에 포함하면 안 된다.
